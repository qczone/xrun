# 中转流量统计

Rust 与 Cloudflare 使用同一套 `TrafficQuery` / `TrafficReport` 契约。没有流量额度、套餐或速度策略。业务明文、Job、文件、截图和成员清单继续由端点持有。

## 计量

有效二进制帧通过当前会话绑定及大小／窗口校验后，入站按帧长度累计；成功交给对端 WebSocket 发送队列后，出站按同一长度累计。控制文本、ACK、缓存声明、认证与 ping/pong 不计入。失败的发送可以形成入站大于出站，这不是统计重复。出站不证明端点完整接收。

每次计量分别更新网络汇总与可确认身份的设备汇总。入站归属发送者，出站归属接收者，设备角色随方向变化而变化。匿名配对仍更新网络计数，但匿名设备侧不创建设备条目；管理设备侧正常计量。加入前传过的匿名数据不会回填到后来签发的成员 ID。

记录的是内层 TLS 密文长度，包括加密握手、业务头和协议开销；不记录帧内容，也不能按业务种类分类。外层 TLS/WebSocket/TCP/IP 开销及网络重传不在这些计数中。网络转发量采用出站即可，不能再加一遍入站。

## 持久化

Rust 使用私有中转数据目录的 `traffic.sqlite`（独立 schema 1）；CF 使用每网络 DO 的 SQLite Storage。只保存每日增量汇总，每个方向的网络／设备更新在事务内完成，不写逐帧事件，不依赖在关闭连接时才结算。查询、缓存复用、重连和休眠恢复都不会重复累加帧。

`traffic_usage_daily` 字段：`network_id`、`device_id`、`day_ms`、`ingress_bytes`、`egress_bytes`、`first_seen_ms`；主键为 `(network_id,device_id,day_ms)`，空的 `device_id` 表示网络汇总。`day_ms` 是 UTC 日期起点。每日计数保留，累计查询直接汇总，不维护另一套可漂移的总量。

`traffic_metadata` 保存录入是否曾出现遗漏。录入失败不会中断转发，当前实例标记不完整，并立即尝试持久保存标记；后续写入继续补写该标记。无法打开／读取存储时查询明确返回 `STORAGE_ERROR`，不伪装成零流量。若存储持续不可写直到进程异常结束，最后的失败标记也可能无法保存，因此这些统计不能直接用作严格扣费账本。

## 查询与展示

`WSS /<路由>/networks/{network}/traffic` 先使用绑定该路径的 challenge/proof 验证身份。带有效网络根私钥签名者可查看全网；只有成员证明者只能查看自身。relay 不接受客户端指定另一个查询设备。服务器发出 `traffic_ready` 后，客户端提交 `traffic_query`；回复 `traffic` 后结束该查询连接。

请求：`query: {period: "today"|"month"|"all", offset: 0, limit: 50}`。缺省为本月、首个设备页，`limit` 为 1–256，`offset` 为无符号 32 位整数。协议的其他普通未知字段可忽略。分页只影响设备列表，不影响总量与趋势。

响应包含网络／设备范围、周期、查询边界、首次记录时间、完整性、入站／出站总量、设备发送／接收列表、每日趋势与 `next_offset`。日趋势补零；累计查询的总量覆盖全部数据，趋势只覆盖最近 30 个 UTC 日期。没有记录时首次时间为 null，所有计数为零。

CLI 使用 `xrun traffic --period all --json`；桌面概览使用同一核心客户端 API。页面可见且没有本地操作时每 10 秒刷新，切换网络或周期丢弃旧请求结果；暂时读取失败保留并标明旧快照。

统计只属于当前中转部署。部署更新保留存储时可继续累计；换中转、删除存储或删除 CF namespace 后不自动找回／合并其他部署的数据。
