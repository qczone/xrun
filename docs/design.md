# xrun 设计文档

本文描述当前代码的架构、行为契约与验收边界。项目介绍见 [README.md](../README.md)，使用说明见 [usage.md](usage.md)，开发与发布说明见 [development.md](development.md)。

## 1. 概述

### 1.1 目标

xrun 让开发者和 AI Coding Agent 在已授权的 macOS、Windows、Linux 设备上执行命令、管理后台任务、传输单个文件、访问开发服务和截图检查效果。程序与参数直接传递，脚本显式选择 Shell；文件在本地使用自己的工具读取和编辑。调用方必须指定目标设备。

设备主动连接自建 Linux 中转或 Cloudflare 中转，无需向客户端开放入站端口。中转可以放在公网服务器或所有设备都能访问的内网机器上。创建网络的设备成为唯一管理设备，负责签发成员身份；目标设备自己验证来源并决定授权。

xrun 集中做三件事：

1. **便于部署**：Linux 主机安装中转或部署 Cloudflare Worker，任意客户端创建网络，其他设备通过一次性邀请加入，使用用户级后台服务。
2. **便于调用**：设备开头的命令、结构化参数、明确退出码和 JSON 结果，可以组合构建、测试、文件传输和截图流程。
3. **明确执行结果**：可靠任务的状态、日志和去重记录只保存在目标 daemon；断线后查询原任务，结果无法确认时返回 75。

### 1.2 设计原则

- 同一个逻辑设备持续使用不可变的 `device_id`；设备名是可读别名，证书证明持有对应私钥。
- 成员身份、目标授权与数据中转分开。中转不能签发成员、授予执行权限或解密业务。
- 日常调用不依赖管理设备在线；新设备加入和普通成员证书续期需要管理设备的 daemon 在线。
- 可靠任务独立于连接，重试沿用原 `request_id`；流式执行和转发随连接结束，二者不混用。
- 结果未确认时先查询，不根据相同命令或当前文件内容推测之前是否执行。
- 保留持久化、去重、进程清理、背压与资源上限；按实际使用需求扩展功能。

### 1.4 使用场景

- 本机驱动另一平台完成构建和测试，断线后查询结果并补读日志。
- pull → 本地编辑 → push，保留文件原始字节，按需使用摘要防止覆盖修改。
- start 启动图形程序，通过日志确认就绪，截图查看效果，再取回产物。
- exec 运行项目自己的无头浏览器脚本，pull 取回图片；不依赖远端桌面会话。
- forward 将远端回环开发服务映射到本机浏览器可访问的回环端口。
- `-i` 传递大输入并实时接收输出，由本地管道组合远端程序。

## 2. 架构与信任

### 2.1 组成

```text
开发者 / AI → 本机 CLI → 本机 daemon（运行时复用会话）
                  │ 主动连接
                  ▼
          Rust / Cloudflare 中转：接通连接、转发密文
                  ▲
                  │ 主动连接
              目标 daemon

本机 CLI / daemon ←──── 设备间双向 TLS ────→ 目标 daemon
管理设备：签发证书与成员清单；不在普通成员的业务路径上
目标 daemon：验证身份、检查授权，保存任务、日志和去重记录
```

| 组件 | 职责与数据 |
| --- | --- |
| 中转（Rust `xrun relay` 或 Cloudflare Worker） | 只保存在线连接与临时转发状态；按网络 ID 无状态验证成员证书，接通连接并转发密文，不保存或读取成员清单 |
| 管理设备（`xrun up --relay ...`） | 保存网络根私钥、权威成员数据库和邀请摘要；签发成员证书、清单和配对授权结果 |
| CLI（`xrun`） | 发起调用、展示输出、保存本机提交记录和取回文件 |
| daemon（`xrun daemon`） | 从端到端证书确认来源，检查本机授权，执行、清理进程和处理传输；通过私有 IPC 为本机 CLI 缓存出站会话 |
| 桌面 App | 调用核心库管理本机，读取本机任务与操作记录；执行仍由独立 daemon 完成 |

CLI、Linux Rust 中转和 daemon 由同一个 Rust 二进制提供；Cloudflare 中转是单独部署的 TypeScript Worker + Durable Object。App 是独立的 Tauri crate，使用同一核心库并打包配套 helper。CLI 与 daemon 共用设备身份。只运行 CLI 的设备可以发起调用，运行 daemon 才能被调用并为本机 CLI 缓存会话；管理设备也必须运行 daemon 才能接收加入和续期请求。

中转主机可以另行作为普通成员加入网络，两种角色相互独立；安装中转不会自动成为管理设备，也不生成网络根私钥。

### 2.2 两层连接

1. 设备通过外层 HTTPS/WSS 连接中转，Rust 中转固定传输 CA 公钥指纹，Cloudflare 中转使用公共 WebPKI 根；两者验证证书、有效期与地址 SAN。所有请求使用部署时生成的固定随机路由，完整地址需要保密。中转对每个状态、控制和接通请求发出随机挑战：成员出示证书，并用私钥签名绑定网络、设备 ID、接口路径和挑战的凭证。网络 ID 就是网络根公钥指纹，所以中转只需确认证书链到这个根、证书属于声明的设备 ID 且签名有效，无需成员清单。撤销仍由端点判断；被撤销的设备在证书到期前只能以自己的 ID 连接中转，不能冒用其他设备。
2. daemon 用成员凭证保持一条控制连接并接收会话通知；只有持有某设备私钥的连接才能占用该设备的路由。管理设备另用网络根私钥签名同一挑战，中转据此标记管理设备。没有成员证书的配对连接（加入、过期续期）只能接通已标记的管理设备。新会话按需建立，中转通知目标 daemon 为该会话回拨，将两端接通；本机 daemon 可保留已完成请求的会话供后续 CLI 调用。
3. 接通后两台设备在隧道内建立双向 TLS，验证网络根、证书、预期目标 ID，以及成员清单中登记的公钥和撤销状态。
4. 双方交换签名清单，保留已见到的最高版本；目标从客户端证书取得来源 ID，再检查本机授权。中转提供的路由 ID 只用于选连接，身份来自端到端证书。info 详情和清单回执通过设备间加密连接传递，不要求执行授权；status 只展示中转报告的连接提示。
5. TLS 内直接传递 WebSocket 帧，省去内层 HTTP Upgrade；外层 WSS 握手保持不变。同一会话依次处理请求，每条连接同时只有一个在途操作；不同会话使用独立连接和背压。

本机 daemon 通过私有 IPC 为 CLI 缓存出站会话：macOS/Linux 使用私有临时目录中的 Unix socket 并核对用户，Windows 使用只允许所有者和 SYSTEM 的本机命名管道。端点地址、随机凭证和版本保存在私有 `daemon-ipc.json`，请求还绑定本机身份。每个目标最多一条空闲连接，本机总共最多三条，空闲 75 秒或证书到期时关闭，空缓存不启用定时轮询。这覆盖三目标的 10–60 秒间隔调用；空闲缓存仍计入现有中转预算，但协议 2 中转在满额时回收最早声明空闲的会话，为新连接让出名额，不回收活跃会话。旧中转协商协议 1 时，新版 daemon 不保留空闲缓存。

CLI 收完结果和 `Complete` 后显式归还连接；本机中断、错误、未完成读取都关闭连接。借用缓存前发送不含操作的 `SessionProbe`，目标重新检查授权、暂停代次、成员版本与证书期限，并返回当前默认目录和数据库 ID。身份、证书、中转地址或成员清单变化使缓存失效，需要重建会话、重新交换签名清单。仅此提交前探测允许换连接重试；已经提交的任务仍按原请求 ID 查询，不能自动重放。

可靠执行、jobs、wait、logs、kill 和文件操作可以归还会话；流式执行和端口转发可以借用空闲会话，使用期间独占连接，结束后关闭，不归还缓存。status、info 和配对使用各自的查询或管理流程。CLI 在本机 IPC 端点不存在或连接被拒绝、且尚未发送本机请求时直接建立远程连接；IPC 版本不匹配、权限错误、超时或发送本机请求后失败，不改走直接提交。

缓存连接仍占用中转和目标 daemon 的会话名额。中转返回 `SESSION_LIMIT` 时，本机清空空闲缓存并返回本次未提交的失败，不自动重发业务请求。私有 IPC 最多同时转发 32 个操作，连接处理任务总数最多 64 个；已认证的停止请求不占操作名额，长时间流式调用占满操作名额时仍可正常停止 daemon。

**任务**是有持久化状态的可靠执行；**会话**是一次连接。可靠任务在会话断开后继续；流式执行与 TCP 转发属于会话，断开后清理。CLI 重开会话可以查询可靠任务、等待和补读日志。

### 2.3 网络身份与成员清单

网络 ID 为 `net_<网络根公钥 SHA-256 指纹的 base32>`。首次创建或注册生成随机 `dev_` 设备 ID；任务、授权和去重使用 ID，名称仅用于选择设备。更换地址和续期不改变 ID。

管理设备签名的完整清单包含：网络 ID、递增版本、管理设备 ID、成员 ID/名称/公钥指纹/撤销状态、中转地址和中转 CA。权限不放进清单。

- 加入、邀请消费与成员版本变更由管理数据库事务协调；CLI 和 daemon 并发修改时由 SQLite 串行处理。
- 只有端点验证清单签名和网络 ID。设备将最高版本持久保存在 `roster.db`；旧清单不覆盖新清单，同版本内容不同返回 `ROSTER_CONFLICT`。
- 已有成员不能被删除、改名、换公钥或重新激活；撤销记录保留。名称可由新的未撤销设备复用，旧 ID 不复用。
- `roster.db` 缺失时拒绝丢弃最高版本记录；管理数据库或根私钥缺失时拒绝重建权威状态。
- 一个网络最多记录 256 个成员（包含已撤销成员）；管理设备最多保留 256 个有效邀请。

签名只能证明清单来自管理设备。中转可以扣住更新，两个持有同一旧清单的设备也不能判断全网是否存在更高版本；本地最高版本不是“全网最新”的证明。

### 2.4 撤销与送达

只有管理设备能执行 `xrun revoke <设备>`，管理设备不能撤销自己。操作先在本机提交并签名新清单，再经端到端连接同步给在线端点，包括尝试通知被撤销目标以关闭其已有会话；同步失败仍保留本地撤销，不回滚。

在线 daemon 验证更新并用自己的私钥签名确认清单版本和哈希。管理设备检查回执，返回 `device_id`、`revoked`、`roster_version`、`undelivered` 和 `sync_error`；没有有效回执的未撤销成员列入 `undelivered`。重复撤销同一个 ID 不增加版本，可以重新同步并查询送达。

收到撤销的设备拒绝该来源并关闭其会话；已受理的可靠任务继续，不自动取消，也不回滚副作用。流式执行随会话关闭清理，转发连接关闭。

**撤销只对已收到记录的设备确认生效。** 离线或被中转隔离的设备可能继续接受旧清单中的来源。业务连接建立时可同步双方已知的签名清单，但不能保证取得全网最新状态。紧急阻断在目标本机执行 `deny-from <设备ID>` 或暂停远程访问；不依赖中转送达。

### 2.5 本机授权与暂停

每个 daemon 在 `daemon.toml` 保存授权，以不可变设备 ID 为键。成员资格与执行授权分开：加入网络默认不授予执行、传输、截图、任务查询或转发权限。

授权判断顺序为：有效且未撤销的成员 → 未暂停 → 未被单独拒绝 → 在白名单中或开启全体信任。任务查询、日志和取消还要核对任务属于该来源，不能操作其他来源的任务。

| 操作 | 行为 |
| --- | --- |
| `allow-from <来源>` | 允许来源访问本机，同时移除其单独拒绝记录 |
| `deny-from <来源>` | 拒绝来源并移除其白名单记录；优先于全体信任 |
| `allow-from --all` | 接受本机已验证清单中的所有未撤销成员，包括以后加入的成员；默认关闭 |
| `deny-from --all` | 关闭全体信任，保留单独允许和拒绝记录 |
| `daemon pause` | 持久保存暂停状态，拒绝新业务请求，使已有会话失效并关闭活动会话；可靠任务继续 |
| `daemon resume` | 恢复原授权；已关闭的会话不会重新启用 |

授权在被控设备上修改。直接指定设备 ID 的单独授权/拒绝、全体信任和暂停可在本机离线执行；按名称修改权限时 CLI 需要查询设备列表。配置使用同一文件锁修改，热更新每 100 ms 检查，暂停代次保证快速暂停再恢复也能使旧会话失效。暂停跨 daemon 重启保留，不暂停管理设备的配对通道。

默认邀请只注册。`invite --allow` 或 `up --allow` 根据管理设备签名且绑定双方 ID 的配对结果，让管理设备与新成员互相授权；与第三台设备仍需分别授权。注册重试和续期不覆盖已有单独拒绝。带授权的邀请等于管理设备当前用户的命令执行权，应通过可信渠道分享。

### 2.6 桌面 App

桌面 App 使用独立的 Tauri 2 crate，直接调用核心库中的网络创建、加入、状态查询、授权、邀请和撤销操作；CLI、中转和 daemon 仍可单独构建。界面使用 React + TypeScript，以 Vite 构建为包内静态资源，Bun 负责依赖、开发脚本和界面测试；发布包不包含 Bun 运行时。不加载远端网页，也不提供前端 Shell 或文件系统访问接口。身份私钥和证书不作为状态 DTO 传到前端。部署链接和成员邀请的输入只用于当前操作，不持久化到 WebView；生成的成员邀请只在设备页的邀请弹窗展示，复制时由原生后端写入剪贴板，不读取剪贴板。

App 与 daemon 是两个进程。关闭窗口、隐藏图标或退出 App 不影响 daemon；单实例机制和 macOS reopen 事件负责恢复图标与窗口。执行和传输仍由独立 daemon 完成。

App 以只读连接读取本机 `daemon.db` 中已有的任务、输出和文件操作记录，使用游标分页，后台服务停止和网络断开时仍可查看。任务详情校验数据库 ID，重建数据库后旧任务引用不能读取新库中的同名任务。日志以序号增量读取、分别解码 stdout/stderr 的 UTF-8 字节并按纯文本展示，预览保留最近的输出，界面内存有上限；输出截断、过期和结果丢失分别提示。不增加 daemon RPC 或第二份任务状态，不向其他设备开放本机全量记录。执行环境和权限的本地修改使用同一文件锁，保存时保留其他配置。

macOS 包内 LaunchAgent 使用 `BundleProgram` 指向配套 CLI，通过 SMAppService 注册，系统将后台服务关联到 xrun.app。Windows 配套 helper 使用 GUI subsystem，登录计划任务以当前用户的普通权限运行；App 登录启动单独配置。服务管理显式传入 helper 路径，避免误注册桌面程序自身。已有 CLI 服务只在停止后、用户点击启动时迁移。

daemon 在私有设备目录中写入 `daemon-runtime.json`，包含本次运行的随机代次和已确认的连接状态。App 通过私有 IPC 携带 daemon 代次请求正常退出；daemon 用事件通知等待，旧的停止请求不会影响新的实例。停止后先取消并等待任务清理，再以成功状态退出，异常重启策略不会把它立刻拉起。IPC 只接收本机用户连接，不监听 TCP 端口。

后台服务的注册决定下次登录是否启动；停止只结束本次运行，移除服务取消注册但保留设备数据。App 的登录启动与服务注册分开。Windows 安装包更新前正常停止 helper，卸载时只清理指向本安装目录的计划任务和 App 登录项。

App 的本机概览从已验证的本地成员清单读取管理角色、管理设备名称和中转地址；中转不可达时仍可显示。设备名称、ID、管理角色和撤销状态来自签名清单；连接提示来自中转，按本机清单过滤；列表不查询平台信息，也不把连接提示作为身份或执行能力的证明。

- 未加入时可以选择创建或加入。创建使用 Cloudflare 输出的完整 HTTPS 地址或 Rust 的 `xrun-relay://` 部署链接，本机成为管理设备；加入使用 `xrun://` 成员邀请。成功后启动后台服务，创建后进入设备页。创建途中已保存身份但网络发布未完成时，保留输入以便重试；注册或创建已经完成、仅服务启动失败时，清除链接并提示单独启动服务。
- 只有管理设备显示邀请与撤销控件，后端仍校验管理权限。邀请默认不授权，开启互相访问须确认；App 要求后台服务已连接，便于新设备随后加入。CLI 生成邀请本身不要求 daemon 在线，但新设备加入要求它在线。
- 生成的邀请仅当前弹窗展示；关闭弹窗、离开页面、切换网络、角色改变、过期或点击隐藏后清除显示，迟到结果不再展示。隐藏不撤销服务端仍有效的邀请。复制只在用户点击时写入系统剪贴板；剪贴板内容不会随页面清除而自动删除。
- 撤销确认后显示本地保存结果、同步错误和未确认送达的成员名称及 ID；可重新同步。同一个结果中不把未送达成员显示成“已全部生效”。
- 本机概览分别显示后台服务、中转连接和远程访问状态。本机访问设置明确表示其他设备对本机的单向授权，提供单独允许/拒绝、全体信任和暂停，并显示授权来源。全体信任在高级访问策略中配置，撤销成员身份与访问开关分开。活动记录展示本机数据库，命令和结果优先，宽窗口并排显示列表与详情；向上滚动暂停自动滚动，不停止增量读取，返回列表保留分页和阅读位置。活动旅程从同一 jobs 表读取所有操作；文件和截图保留独立附件，可预览和另存为。

### 2.7 安全边界

| 对象 | 信任与限制 |
| --- | --- |
| 中转 | 不信任其业务身份判断；不能解密端到端业务或伪造管理签名，但可中断、限速、隔离设备和延迟清单 |
| 管理设备 | 受信任，根私钥被盗会破坏成员身份体系；授权来源在其用户权限下执行也可能读到该私钥 |
| 被授权来源 | 拥有目标用户可执行命令、访问文件和截图的能力；不提供命令级沙箱或多用户隔离 |
| 本机存储与输出 | 数据库、参数和日志可能包含敏感内容；远端输出原样透传，终端控制字符与 AI 提示注入由使用方处理 |

中转可见网络 ID、网络根证书、连接时出示的成员证书（设备 ID、公钥与有效期）、来源 IP、在线连接、时间和流量。设备名称、撤销记录、主机名、用户名、默认目录和回执均通过端到端连接交换，中转无法读取。邀请 Token 只在已验证管理设备的端到端配对通道内发送；程序、参数、环境值、输入、输出、文件与截图内容经设备间 TLS 加密。权限仍由目标自己判断。

首版只有一个管理设备，不提供根密钥轮换、第二管理设备或管理身份恢复。管理状态丢失后重新组网；不能通过重新运行创建命令将旧数据库替换成新的权威状态。

## 3. Linux 中转与网络部署

### 3.1 中转运行条件

Rust 中转部署命令只支持 Linux。使用 systemd 用户服务并启用 linger，用户退出后继续运行并在开机后启动；没有 systemd 时，先准备持久配置，再用 `xrun relay run` 前台运行，由使用方管理进程。

默认监听 TCP 9528，绑定 `0.0.0.0`。中转传输连接仅支持 IPv4；指定域名需有 A 记录。IPv6-only 网络不支持；业务转发在目标回环上可另行尝试 `::1`。使用方放行入站端口，xrun 不自动修改防火墙或云安全组。

最多 512 条 TCP 连接，每个 IP 最多 16 条未认证连接，升级后的 WebSocket 仍占总连接名额。TLS 握手和 HTTP 请求头分别等待最多 10 秒，升级前整个 HTTP 连接最多 30 秒；非升级响应要求关闭连接。accept 失败记录日志并间隔 250 ms 重试，不退出服务。成员凭证验证通过后连接不再计入未认证名额；会话按真实来源 IP 限制并发，不信任转发头。限制缓解资源耗尽，不保证持续攻击下的可用性。

### 3.2 安装中转

```bash
xrun relay install --addr 192.168.1.10:9528
```

命令生成或复用中转传输 CA、服务端密钥和固定随机路由，保存监听配置，安装 systemd 用户服务，输出可重复使用的部署链接。中转不创建客户端或管理身份。

| 参数 | 行为 |
| --- | --- |
| `--port <端口>` | 实际监听端口，首次默认 9528；重复安装显式修改时重启服务 |
| `--addr <主机>:<端口>` | 可重复或用逗号分隔；替换发布地址并持久设为手动模式；不代替 `--port` |
| `--no-detect` | 自动模式下禁用公网 IP 查询，只使用网卡地址；设置持久化 |

例如使用 8080：`xrun relay install --port 8080 --addr 203.0.113.10:8080`。发布地址可以使用映射后的端口，实际监听端口必须分别设置。

未指定地址时，自动收集非回环、非链路本地的 IPv4 网卡地址，并默认向公共服务查询出口 IP，整个查询最多 2 秒，失败跳过。没有可用地址时要求显式 `--addr`。不识别 Docker/VPN 网卡，也不预先判断候选地址可达性。

`config.toml` 保存 `manual`、发布地址、端口和 `no_detect`。手动模式在重启和省略地址的重复安装时保留，只有显式 `relay install --addr ...` 才替换；自动模式启动时重新探测。出口 IP 不保证外部可达，推荐固定域名或 IP。

中转传输 CA 约 20 年有效，服务端证书最长 10 年，启动时重新签发，包含回环和发布地址 SAN。发布地址变化不改变中转 CA；网络使用的地址仍需管理设备签名发布，自动探测不会自动修改各网络的清单。

中转服务内部仍使用 `server` 标识与 `xrun-server` 服务名，`xrun server` 是隐藏的兼容服务入口，实际运行中转。

#### Cloudflare 部署

正式代码位于 `cloudflare/`。使用 `bun install --cwd cloudflare --frozen-lockfile` 安装依赖，`bun run --cwd cloudflare deploy --name xrun-relay` 部署。脚本从 Cargo.toml 读取完整版本，部署 Worker 和 SQLite-backed DO 类 `XrunRelay`，将随机路由写入 Worker secret，输出完整 HTTPS 地址。同名重复部署保留路由；`.deploy/<名称>.json` 以 0600 保存部署状态，目录为 0700，不纳入 Git。删除命令只接受有本地部署记录的名称，先 migration 删除 DO 类与命名空间，再删除 Worker。

每个网络对应一个 DO。没有成员、配额、任务或文件数据表；在线控制连接、会话代次、接入 ID 和未确认密文字节数随 WebSocket attachment 保存，休眠后重建连接关系。alarm 仅清理认证超时、待接入和闲置传输；没有持续运行的 JS 心跳，原生 ping/pong 由 CF 运行时处理。

每网络最多 512 个 WebSocket、256 个控制连接、8 个来源会话（含待接入）；每 IP 最多 8 个正在验证的连接；每目标匿名配对最多 4 个。`connected` 携带 `flow_control: true`；每方向最多 4 MiB 未确认密文，8 个双向会话的未确认密文预算合计最多 64 MiB，此外仍有运行时、连接和消息对象开销。接收端写入本地 TLS 通道后，每累计 256 KiB 回复 `{type:"ack",bytes:N}`，不足阈值的尾部计入下一批，中转校验确认量后通知发送端释放窗口。超过 64 KiB 的帧、超出窗口或非法确认会关闭两端。窗口不限制累计传输量，单文件大小不设固定上限。

签名清单中的 `relay_ca_pem` 为空时选择公共 WebPKI，邀请链接的中转指纹段为 `webpki`；网络根指纹仍固定，成员和执行权限仍在内层验证。中转信任方式也受管理签名约束。公共中转地址仅接受单段合法随机路径，不允许用户名、查询参数或 fragment。

### 3.3 创建网络与邀请

在任意 Mac、Windows 或 Linux 设备上使用中转输出的完整部署链接：

```bash
xrun up --relay 'xrun-relay://192.168.1.10:9528/<中转指纹>#<随机路由>' --name mac1
```

1. 验证中转 TLS：Rust 中转固定传输 CA 指纹，公共 HTTPS 中转使用 WebPKI；创建本机网络根密钥、管理设备身份和版本 1 的成员清单。
2. 将管理状态、身份和已验证清单持久保存，不向中转登记网络或发布成员信息。
3. 初始化本机任务数据库，默认安装 daemon；`--no-daemon` 只准备身份与数据库。
4. CLI 生成下一台设备的成员邀请并打印 `join` 命令；App 创建后在设备页单独生成邀请。

部署链接格式为 `xrun-relay://<地址列表>/<中转CA公钥指纹>#<随机路由>`。路由为 128 位随机数，base32 编码 26 字符，部署和重启时复用，客户端将它转为 HTTPS 地址的一段路径。`xrun relay invite` 显示同一部署链接，不新增邀请记录。完整地址必须保密；成员邀请里也含有该路由，过期后路由仍然有效。知道路由只能向管理设备发起配对，占用设备路由、查询在线设备和接通其他设备都需要成员凭证。中转不登记网络，不签发成员，也不按成员判断执行权限。

成员邀请格式为：

```text
xrun://<含随机路由的地址列表>/<网络ID>/<管理设备ID>/<网络根指纹>/<中转指纹>#<Token>
```

网络根指纹为 SHA-256 公钥指纹的小写 base32（52 字符）；Rust 中转指纹使用同一格式，公共 HTTPS 中转的这一段为 `webpki`。成员 Token 同样为 128 位随机数、10 分钟有效、一次使用，由管理设备保存摘要。只有管理设备可生成邀请或撤销成员；普通成员返回 `NOT_MANAGER`。配对受理时按管理设备本机时钟判断过期。

网络根约 20 年有效，成员证书最长 365 天且不超过根有效期。设备证书同时支持 TLS 客户端和服务端认证，SAN 使用由设备 ID 派生的名称，不依赖设备公网地址。剩余不足 30 天时尝试用原私钥续期；daemon 启动、控制重连以及每 5–6 分钟的后台维护都会检查，管理设备恢复在线后可继续重试，不依赖用户运行 CLI。普通成员经配对通道联系管理设备，管理设备可本地续自己的证书。续期失败但原证书仍有效时继续使用；已过期时必须等管理设备续期，不能继续业务调用。

配对身份、清单和邀请授权持久化后立即返回结果，再尽力同步其他在线端点；无关慢设备不阻塞加入方。已登记公钥重试时返回同一 ID、原配对结果和新证书，不消费新 Token；被撤销公钥拒绝重入。新公钥仅在有效邀请下加入；名称占用不消费 Token。身份私钥不是设备 ID，知道 ID 不能恢复身份。

### 3.4 日常连接与更换中转

| 情况 | 行为 |
| --- | --- |
| 管理设备 daemon 离线 | 已有普通成员可以互控、传文件、截图和转发；新加入与普通成员续期不可用 |
| 中转离线 | 无法建立或保持远程会话；已受理可靠任务继续执行，恢复后可查询 |
| 目标 daemon 离线 | 返回 `DEVICE_OFFLINE`，不排队；已知撤销目标返回 `DEVICE_REVOKED` |
| 管理设备本机签名撤销但端点同步失败 | 本地结果保留，报告同步错误和未送达成员，可以重试同步 |

首次创建可重试，保留已有根密钥与身份；不隐式生成新网络。已有管理设备用新部署链接重复 `up --relay ...` 时，可以签名更新中转地址/CA，无需向新中转登记，并通过旧中转上的加密端点连接尽力同步地址变更；需 daemon 已停止，名称不可改变。普通成员不能以 `up` 接管管理身份。

一个网络同时使用一个中转，可以有多个可达地址。收到已验证更新的成员使用新中转；未收到的成员可通过同一网络的新邀请重新 `join` 更新配置。旧中转可能扣住通知，当前创建命令不提供完整迁移送达报告，不能宣称所有成员已经自动切换。

客户端记住同一网络上次验证成功的地址，下次仍在候选列表中就先试。缓存只改变连接顺序，每次仍验证 TLS 与签名。按地址串行尝试：创建网络时探测中转 TLS 每地址最多 5 秒，普通外层连接建立每地址整体最多 10 秒，加入配对每地址整体最多 30 秒；不并发探测多个地址。

### 3.5 中转存储

| 位置 | 内容 |
| --- | --- |
| `~/.xrun/config.toml` | 监听端口、发布地址、探测模式与中转数据目录 |
| `~/.xrun/server/` 密钥文件 | 中转传输 CA、服务端证书和私钥；没有网络管理根私钥 |
| `~/.xrun/server/route` | 固定随机路由；部署链接与客户端地址使用同一值 |
| 进程内存 | 已验证的控制连接（含管理设备标记）与会话配对；断开后清理，重启后不恢复 |
| 服务日志或前台 stderr | 连接与转发诊断，非业务原文 |

中转不保存可靠任务、命令参数、业务输出、文件或图片内容。目录 0700、私有文件 0600；设备侧 Windows 使用当前账户和 SYSTEM 可访问的私有 ACL。中转的证书、配置与随机路由和管理设备的根密钥/权威数据库应分别保管。

## 4. 客户端

### 4.1 加入：`xrun join`

```bash
xrun join '<管理设备输出的 xrun:// 成员邀请>' --name cloud1
```

1. 解析邀请中的网络、管理设备与双重指纹，尝试中转地址，核验中转 TLS。
2. 通过受限配对通道连接管理设备，先固定网络根指纹、验证其 TLS 和预期管理 ID，之后才发送 Token 与 CSR。新设备不需要成员证书，匿名通道只允许配对，不能执行任务。
3. 在发送注册请求前，将私钥、已核验根证书和指纹持久保存到 `pending.toml`。失败保留；重试使用同一私钥，不创建第二台设备。
4. 管理设备验证 CSR 私钥持有证明、邀请与名称，在事务内消费 Token、注册 ID、保存签名配对结果和新清单。
5. 客户端验证证书、清单、公钥和配对签名，先保存清单，再原子保存完整 `identity.toml`；应用本机授权时保留已有单独拒绝，成功后删除暂存文件。
6. 初始化任务库并默认安装 daemon；`--no-daemon` 只准备身份和数据库。服务安装失败后可以重试补完，不重新注册。

`--name` 指定首次名称，省略时按主机名生成。已有身份再次 `join` 只接受同一网络，保持私钥、设备 ID、任务和执行配置，取得当前清单及证书；无需重新消费邀请。不同网络返回 `NETWORK_MISMATCH`，已撤销身份返回 `DEVICE_REVOKED`，不自动注册新身份。

本机只加入一个网络，不在运行中切换身份。需要清理或重新组网时先结束在途任务、停止服务，再明确处理本机数据；新身份需重新授权，不能用旧 ID 恢复。

### 4.2 daemon 的运行与自启动

| 平台 | 方式 |
| --- | --- |
| Linux | systemd 用户服务；需要 linger 才能退出登录后继续运行 |
| macOS | 用户 LaunchAgent，登录后运行，可以使用登录钥匙串和图形会话中的工具 |
| Windows | 用户登录时的计划任务，运行在交互会话中 |

`join/up` 安装 daemon，也可用 `daemon install/uninstall` 管理服务，或用 `xrun daemon` 在前台运行。每个本机身份只运行一个实例，崩溃后自动重启。daemon 每次建立连接前读取最新身份文件，使用更新后的地址和证书。

首次安装建立数据库；已经初始化后，数据库缺失或损坏时拒绝启动。使用 `daemon reset` 明确重建，旧任务、日志和去重记录丢失，生成新的 `db_id`，设备身份不变。reset 前停止 daemon；运行中的正常停止会取消任务。

daemon 正常退出会取消运行中的任务并持久化结果。升级前应等现有任务结束。

macOS 访问受保护目录仍受 TCC 约束，截图需要“屏幕录制”权限；截图请求缺少权限时明确报错。服务通常不加载交互 Shell 配置，工具链 PATH 放在 `daemon.toml` 的 `[env]` 中。

### 4.3 命令

**指定设备的操作统一把设备放在 xrun 后面：**

```text
xrun <设备> <操作> [参数和选项]
xrun <设备> [执行选项] -- <程序> [程序参数…]
xrun <设备> start [执行选项] -- <程序> [程序参数…]
```

`xrun --help` 和 `xrun --version` 是本机全局选项。其余命令的第一项是本机子命令时，由本机 CLI 处理；否则作为设备名或设备 ID 解析。执行入口中的 `--` 标记远端程序的开始，之后所有参数原样交给程序，不再解析 xrun 选项。没有 `--` 时，只接受已定义的设备操作或显式脚本选项；未知操作返回参数错误。

操作选项放在操作名后，例如 `xrun win1 screenshot --json`。前台执行选项放在设备与 `--` 之间，例如 `xrun win1 -C 'D:\valle' -- cargo build`；后台执行选项放在 start 后，例如 `xrun win1 start -C 'D:\valle' -- 'target\debug\app.exe'`。

常用命令直接写操作意图：执行程序、start 启动后台任务、push/pull 传文件、screenshot 截图、forward 转发端口。后台任务始终使用实际返回的任务 ID 查询或取消。部署、授权、身份管理和总体状态使用本机命令；远端业务使用设备开头的命令。

**本机命令**

| 命令 | 用途 |

**指定设备的操作**

| 命令 | 用途 |
| --- | --- |
| `xrun <设备> [选项] -- <程序> [参数…]` | 执行远端程序 |
| `xrun <设备> start [选项] -- <程序> [参数…]` | 启动后台任务，受理后返回任务引用；默认不限时 |
| `xrun <设备> -i [选项] -- <程序> [参数…]` | 非终端流式执行，无持久任务；断线清理进程 |

| `xrun <设备> info` | 查询本机签名成员身份；目标在线时经端到端连接获取状态，离线时只显示已验证成员记录 |

| `xrun <设备> push <本地源> <远端目标> [选项]` | 上传单个文件；本地源为 - 时读取 stdin |
| `xrun <设备> pull <远端源> [本地目标] [选项]` | 下载单个文件；本地目标为 - 时输出原始字节 |

status 将本机已验证成员清单与中转报告的连接列表合并；info 只向指定 daemon 建立端到端连接获取详情；revoke 由本机管理状态签名，再同步给端点并验证送达回执。执行、任务、传输、截图和转发由目标 daemon 处理。本机 allow-from/deny-from 的参数是来源身份；修改远端白名单可显式执行 `xrun win1 -- xrun allow-from mac1`。

```bash
xrun win1 -- cargo test
xrun win1 pull 'D:\valle\src\main.rs' ./main.rs
xrun win1 screenshot
xrun win1 wait k3m9x2
```

管理设备执行 `down --purge` 会删除网络根私钥与权威成员状态，无法继续签发，需重新组网；中转主机 purge 会删除传输证书与随机路由，各网络需明确更新地址或更换中转。普通成员 purge 后作为新设备加入，旧身份仍需管理设备撤销。清理前先确认未结束和未确认的任务。

### 4.4 设备与任务引用

设备可以用名称或 `device_id` 指定。执行、任务、文件传输和截图的目标设备位于 xrun 后面；revoke、allow-from、deny-from 则以本机命令后的参数指定相关身份。文件路径是独立参数，例如 `xrun win1 pull 'D:\valle\a.rs' ./a.rs`，无需携带设备前缀，也不按 `:` 拆分。Shell 中的反斜杠路径应加引号。

设备名格式为 `[a-z][a-z0-9-]{0,31}`，不得使用本机子命令名或设备操作名。默认由主机名转小写、替换非法字符并截断；结果不合法时使用平台名加 1（例如 macos1），名称占用时通过 `--name` 指定。本版不提供改名命令。

任务短 ID 由 daemon 生成，为 6 个 Crockford base32 字符，在数据库内唯一，冲突时重新生成。人读引用为 `<设备名>/<短 ID>`，稳定引用为 `<device_id>/<短 ID>`。JSON 和本机提交记录同时保存设备 ID 和任务短 ID。

指定设备后，任务参数通常只写短 ID，例如 `xrun win1 logs k3m9x2`。也接受完整任务引用，方便复制；完整引用中的设备必须与前面指定的设备解析为同一 ID，否则返回参数错误，不转发到其他设备。

`jobs` 不带 ID 时列出任务，默认每页 50 条，可用 `--limit` 和 `--offset` 分页；带 ID 时返回该任务详情。`--running` 和 `--request-id` 只用于列表查询，与任务 ID 同时提供时返回参数错误。

更新地址或证书后，稳定引用仍然有效。名称被其他设备复用时，按名称访问的是当前设备；连接重试和 `--request-id` 重试都使用记录中的设备 ID。查询已撤销身份的旧任务时返回 `DEVICE_REVOKED`；未撤销身份的 daemon 离线时返回 `DEVICE_OFFLINE`。两者都不会路由到同名的新设备。

### 4.5 执行选项

| 选项 | 语义 |
| --- | --- |
| `-C <目录>` | 远端绝对工作目录；省略使用 daemon 默认目录 |
| `--env KEY=VALUE` | 可重复，覆盖远端环境变量 |
| `--stdin` | 可靠任务提交前读完本地 stdin，最多 1 MiB |
| `-i`、`--interactive` | 随连接运行的非终端流式执行，输入无 1 MiB 总量限制；见 4.15 |
| `--script <shell>` | 从 stdin 读取脚本，最多 1 MiB；必须指定 Shell |
| `--timeout <秒>` | 从进程启动计时；前台默认 1800，start 默认 0（不限时）；显式指定时覆盖默认值 |
| `--request-id <ID>` | 明确重试同一提交；省略时生成新的 ID |

普通执行等待任务结束并透传输出；start 在任务受理后返回，stdout 输出任务引用。start 成功表示受理，不表示执行成功。需要限制后台任务时长时，显式指定超时，例如 `xrun win1 start --timeout 600 -C 'D:\valle' -- cargo build`。普通再次调用生成新请求，不按命令内容判断是否重复。

`request_id` 由 CLI 自动生成并在发送前持久化，日常调用不需要先运行 UUID 工具或手动提供 ID；`--request-id` 用于显式恢复同一次提交。构建和测试通常前台执行，启动需要继续交互或截图的程序时使用 start。后台提交返回任务引用，后续命令直接使用其中的短 ID；常用示例不要求用 Shell 临时变量保存它。自动化调用可以通过 `start --json` 读取任务 ID。

普通执行与 start 使用同一套可靠任务和 exec 协议。Exec 的 follow 字段控制是否在提交会话中继续跟随日志，默认 false；前台 CLI 设置为 true，该字段不属于 Execution，也不参与去重摘要。start 也接受 stdin 和脚本选项，例如 `xrun linux1 start --script sh < ./serve.sh`；它只改变 CLI 是否等待，以及未指定超时时的默认值。CLI 先解析出实际执行参数，再持久化提交记录并提交。

### 4.6 输出、退出码与 JSON

前台执行按原始字节分别透传远端 stdout 和 stderr。远端程序正常结束时，xrun 不额外输出内容；错误或需要后续确认时在 stderr 打印 `[xrun] <说明>`，附上任务引用或 `request_id`。

| 退出码 | 含义 |
| --- | --- |
| 0–255 | 远端程序的退出码 |
| 1 | Windows 上超出 255 的退出码；完整值写入诊断信息和任务结果 |
| 128+N | 远端进程被信号 N 终止 |
| 124 | 超时，已确认受管理进程停止 |
| 130 | 可靠任务的本地 Ctrl+C，已确认取消或没有受理任务；流式执行见 4.15 |
| 75 | 已受理或可能送达的执行、修改或取消结果未确认，以及等待已有任务结果超时或无法确认 |
| 125 | 请求发送前的连接失败、明确拒绝、执行层错误或任务结果丢失等 |
| 2 | 本地参数错误 |

输出不完整时保留远端退出码，同时注明 `TRUNCATED`、`DETACHED_OUTPUT` 或 `CAPTURE_ERROR`。

其他命令成功为 0，已确认的文件等操作失败为 1，连接或执行层错误为 125，本地参数错误为 2。`jobs` 查询成功返回 0，不受任务结果影响；无任务时返回空列表。

连接与提交失败按当前操作所处阶段处理：

- 执行提交、push 或 kill 尚未开始发送时，连不上中转、目标离线等连接错误返回 125；本次提交、上传或取消请求收到连接、身份、版本或并发检查的明确拒绝也返回 125。此时该操作没有被受理，可以重试；`DEVICE_BUSY` 可以稍后沿用原 request_id 重试。
- 上述请求可能已经送达、但未收到确定结果时返回 75。CLI 记录“请求是否可能已发出”，在开始写入请求前设置；写入报错也不能据此认定未发送。处理期间授权失效、暂停或停止不能证明此前尚未受理，按未确认处理。收到任务引用后，执行结果仍需等任务结束才能确认；本地确认记录补写失败只报告带任务引用的诊断，不隐藏远端已确认的结果。只有收到明确的未受理响应，才可以把这次请求判为拒绝。
- jobs/logs、pull 和截图等只读操作的连接失败返回 125，可安全重试。wait 在等待已有任务结果时，超时、连接无法恢复或目标离线仍返回 75；明确的身份、撤销或版本拒绝返回 125。wait 的 75 不表示提交了新任务，也不能据此重新执行原命令。

125 本身不证明原任务从未执行；`RESULT_LOST`、`DB_RESET` 等仍需先确认原任务。可以直接重试的范围是这次明确未发送或未受理的操作。连接恢复时的新会话被拒绝，不能推翻原操作已受理或可能送达的状态；原操作仍按结果未确认返回 75。执行提交的本机中断恢复仍按原 request_id 查询，不把缺少发送确认当成未执行。

远端程序本身也可能输出诊断前缀或返回相同的退出码。自动化需要可靠状态时，用 `xrun <设备> start --json [选项] -- <程序> [参数…]` 提交，再用 `xrun <设备> wait <任务 ID> --json` 查询；构建和测试需要限制时长时，在 start 上显式指定 `--timeout`。

`--json` 用于状态、设备、任务、文件传输、截图、邀请、撤销结果，以及 start 提交和 forward 的监听信息；前台执行不支持 JSON。采用固定字段，没有精简/verbose 两套格式。`pull … -` 输出文件原始字节，与 `--json` 互斥；`push - … --json` 可以使用，stdin 是上传内容，stdout 是结果 JSON。

start 和 jobs 的 JSON 返回统一 Job 对象，包括 `job_id`、`kind`、`params`、`result`、来源/目标设备 ID、`db_id`、`request_id`、状态和附件。命令退出码、信号和耗时位于 `result`；日志序号与完整性位于 `last_log_seq`、`log_bytes`、`output_complete`、`output_loss_reason`。wait 返回 `{"job":任务对象,"logs":日志事件数组,"logs_error":null或错误说明}`；任务等待和尾部日志读取共用 `--timeout` 的截止时间。已确认任务结果后，补读日志失败或超时不改变任务退出码，具体错误放入 `logs_error`。logs 的 JSON 每行返回一组日志事件。

### 4.7 信号、断线与 AI 使用

以下提交恢复规则用于可靠任务；`-i` 和 forward 的连接行为分别见 4.15 和 4.14。

- Ctrl+C 在执行请求尚未发送时直接返回 130，不创建任务。请求可能已发送时，先查询受理结果再请求取消，最多等待 10 秒；未能确认时返回 75，打印原 request_id。确认取消或确认没有受理时返回 130。
- SIGTERM、SIGHUP 不取消远端任务；执行请求已受理或可能已发送时，打印任务引用或 request_id，返回 75；明确尚未发送时返回 125。
- 前台可靠执行提交后，在同一会话接收任务确认、日志和最终状态；后台 start 只接收任务确认。是否跟随日志不参与请求摘要。执行会话在提交后连接丢失时，最多花 30 秒重新打开会话，按日志序号补读。仍无法恢复时返回 75；任务继续运行。提交前的连接失败按 4.6 返回 125。
- 收到执行或取消的 75 后先查询：已知任务引用时用 `xrun <设备> jobs <任务 ID>`，也可以 wait 或 logs；只有 request_id 时用 `xrun <设备> jobs --request-id <ID>`。没有 ID 时先看 `xrun recent`。push 的未确认按 4.10 处理。
- 要恢复同一次提交，重新提供原参数和输入，并显式传入原 `--request-id`；要再次执行，发起新请求。
- 验证图形效果时，用 start 启动程序，通过日志或应用自己的就绪信号确认窗口已显示，再调用 screenshot；CLI 返回的本地路径可直接交给 AI 看图工具。
- 验证网页时，通过 exec 运行无头浏览器截图脚本，用 pull 取回生成的 PNG；浏览器、依赖和页面就绪由项目脚本处理。
- `doc` 输出构建时嵌入的 `docs/usage.md`，包含这些规则、常用命令、目标路径、超时与 Windows 注意事项；支持按章节查看，更新后随程序重新构建。README 介绍项目，开发、测试与打包说明维护在 `docs/development.md`。

AI 应把“执行未确认”与“已失败”区分开。xrun 不根据相同命令自动阻止 AI 再次执行；使用方必须遵守先查询的规则。

### 4.8 程序、脚本、目录和输入

请求传递 `program` 和 `args[]`，daemon 直接创建进程，不拼接 Shell 字符串。

- 绝对程序路径直接使用；带目录分隔符的相对路径按工作目录解析；只有程序名时按最终 PATH 查找。忽略空 PATH 项，相对 PATH 项按工作目录解析。保留查找到的符号链接入口，不改写为链接目标，保证按启动名称选择行为的程序正常工作。
- Windows 按 PATHEXT 查找；找到批处理时返回 `SHELL_REQUIRED`，由调用方显式选择 `--script cmd` 或 `cmd.exe /C`。参数编码与长度检查由平台层处理。
- 默认工作目录是用户主目录，可配置；不存在时返回 `INVALID_CWD`。路径不展开 `~` 或环境变量。
- 任务继承 daemon 的正常运行环境，但先过滤隐式构建变量：`CARGO_TARGET_DIR`、`CARGO_BUILD_TARGET`、`RUSTUP_TOOLCHAIN`、`RUST_RECURSION_COUNT`、`RUSTC`、`RUSTDOC`、`RUSTC_WRAPPER`、`RUSTC_WORKSPACE_WRAPPER`、`RUSTFLAGS`、`CARGO_ENCODED_RUSTFLAGS`。之后依次应用 `daemon.toml [env]` 和请求 `--env`，允许显式设置这些变量；`HOME`、`PATH`、`CARGO_HOME`、`RUSTUP_HOME`、代理等其他配置继续继承。此规则在所有平台、开发版和发布版中一致，不依赖服务启动方式。xrun 的身份凭证不通过环境变量传给任务。

`--script` 将内容写入私有临时文件，用指定 Shell 执行，结束后删除；脚本原文不写入数据库。

| Shell | 文件与执行 |
| --- | --- |
| `powershell` | UTF-8 BOM；`powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File` |
| `pwsh` | UTF-8；`pwsh -NoProfile -NonInteractive -File` |
| `cmd` | CRLF，只保证 ASCII；`cmd.exe /D /S /V:OFF /C`，使用 cmd 的引号规则保护脚本路径与参数 |
| `sh/bash/zsh` | 原样；使用所选 Shell 执行 |

`--script` 必须显式指定上述 Shell，不按目标平台选择默认值；缺少名称返回参数错误。未安装所选 Shell 返回 `SHELL_NOT_FOUND`。脚本参数写在 `--` 后面；脚本与 `--stdin` 互斥。

cmd 脚本参数不接受双引号或换行，返回 `INVALID_SCRIPT_ARGUMENT`；空格、`&`、`^`、`%` 和 `!` 按字面传入。脚本自身仍须正确引用参数，xrun 不改写脚本内容。

进程默认 stdin 为 EOF。`--stdin` 要求管道或重定向，CLI 先完整读取最多 1 MiB；超限或失败时不提交。daemon 收齐后才启动任务，写 stdin 与读取输出同时进行。进程提前关闭 stdin 时以进程结果为准，其他输入写入错误取消任务并报告 `STDIN_IO_ERROR`。输入可包含 NUL 和非 UTF-8 字节。

### 4.9 进程管理与超时

- Unix 每个任务使用独立进程组；Windows 使用独立 Job Object，在创建进程时关联，并设置 `KILL_ON_JOB_CLOSE`。关联失败时不创建不受管理的进程。
- Unix 取消先 SIGTERM，5 秒后仍未退出再 SIGKILL；Windows 使用 `TerminateJobObject`，没有优雅退出宽限期。
- 主进程退出后清理受管理的残留进程，最多再花 2 秒读取输出。脱离进程组却继承输出管道的后台进程不会卡住任务：结束读取并标记 `DETACHED_OUTPUT`。
- 默认最多 4 个执行名额，由 accepted/running 的 exec 和 stream_exec Job 共享；满时返回 `DEVICE_BUSY`，不排队、不创建任务、不写去重记录。释放名额后可靠提交可以用原 request_id 重试。
- 超时包含系统睡眠，不受系统时间调整影响。Linux 用 `CLOCK_BOOTTIME`，macOS 用 `mach_continuous_time`，Windows 用 `GetTickCount64`。
- 至少每秒检查截止时间。设备恢复后发现超时，立即执行终止；睡眠期间不唤醒设备。网络断开不影响计时。

脱离 Unix 进程组的进程不受管理；取消和超时的保证限于受管理的进程。终止失败时不能提前报告已取消或已超时。

Unix 使用 `waitid(WNOWAIT)` 观察主进程退出，保留其可等待状态；清理进程组并移除运行记录后才回收主进程，避免向已复用的进程组 ID 发送信号。

### 4.10 单个文件传输

push、pull 和截图请求均先持久化 Job 再执行，使用相同来源白名单，共享每台设备最多 8 个请求的并发上限。文件传输只处理单个文件，内容为原始字节，不解析文本、编码、换行或编辑指令。

远端路径可以绝对或相对于 `-C`、daemon 默认目录；相对路径用 `/`。本版只接受 UTF-8 路径。远端路径跟随符号链接；push 写入链接目标，保留链接本身。文件源和已存在的目标必须是普通文件，符号链接按目标类型检查；目录返回 `IS_DIRECTORY`，其他不支持的文件类型返回 `INVALID_PATH`。push 的远端目标可以尚不存在。

| 命令 | 行为 |
| --- | --- |
| `xrun <设备> push <本地源> <远端目标> [-C 目录] [--expect sha256] [--mkdir] [--no-overwrite] [--json]` | 分块上传单个文件，不设固定大小上限；本地源为 - 时读取 stdin；校验完成后原子写入，成功输出远端绝对路径 |
| `xrun <设备> pull <远端源> [本地目标] [-C 目录] [--json]` | 分块下载单个文件，不设固定大小上限；校验完成后保存，stdout 输出本地绝对路径；本地目标为 - 时输出原始字节 |

路径按**源、目标**排列。push 的两条路径都必填；pull 省略本地目标时保存到系统临时目录中的唯一文件。本地相对路径以 CLI 当前目录为准，`-C` 只影响远端路径。目标按文件路径处理，不自动拼接文件名；创建远端父目录用 `--mkdir`，本地父目录需已存在。

pull 和截图保存到指定本地路径时，拒绝最后一级符号链接（包括悬空链接），在同目录写入临时文件并原子替换该文件名，不跟随最终目标。已有普通文件保留权限位；Windows 的本地新文件继承父目录 ACL。父目录可以解析符号链接，调用方应选择可信的保存目录；此规则不构成文件系统沙箱。

```bash
xrun win1 push ./config.json 'D:\valle\config.json'
xrun win1 pull 'D:\valle\artifacts\page.png' ./page.png
xrun linux1 pull /repo/config.json -
printf '%s\n' 'hello' | xrun linux1 push - /repo/note.txt
```

这里的 - 只用于 push 的本地源或 pull 的本地目标。push 从 stdin 读取时，CLI 先按块将完整输入保存到私有临时文件，不设固定总量上限；输入读取失败不提交。pull 输出 stdout 前也先完成下载与校验。`pull ... - --json` 返回参数错误；`push - ... --json` 可以使用。

push/pull 按固定大小分块读写，SHA-256 随读取或写入累计，不将整个文件装入内存。push 普通文件先计算摘要，再从同一个打开的文件句柄发送；两次读取内容不一致时，接收方因长度或摘要不符拒绝上传，保留原目标。pull 在目标 daemon 上先生成私有临时快照，使摘要对应实际发送的字节。完整响应后的会话归还与关闭见 6.2。

pull 的 JSON 返回 `path`（本地绝对路径）、`device_id`、`remote_path`、`size`、`sha256`、`job` 和 `request_id`；push 的 JSON 返回 `device_id`、`remote_path`、`size`、`sha256`、`job` 和 `request_id`。`job` 为目标设备与 Job ID 组成的引用。摘要对应实际传输的字节，为完整 SHA-256。JSON 不混入路径文本或文件内容。

`push --expect` 是可选覆盖条件，使用修改前从远端下载的摘要，接受 64 个十六进制字符。不匹配或目标已不存在时返回 `STALE`，不覆盖文件。不带时正常创建或替换。`--no-overwrite` 使用操作系统“目标存在则失败”的原子操作，存在时返回 `ALREADY_EXISTS`。这两个覆盖条件互斥，同时提供时返回参数错误。

push 收齐并校验内容后，在目标同目录写入临时文件、fsync，再原子替换。保留远端已有目标的权限；Windows 保留属性和 ACL。不复制本地源文件的权限，也不转换内容。daemon 按解析后的真实路径串行处理 push；带 --expect 时在锁内比较目标摘要，并在替换前再次检查，变化时返回 `STALE`。最后检查与替换之间仍有窗口，不提供与外部程序的严格互斥。目标被占用、无法替换时返回 `FILE_BUSY`。

**pull 失败后可由调用方重新执行，CLI 当前不自动重传文件；push 在响应丢失后不自动重发，也不根据当前哈希推断此前是否成功。** push 结果未确认时 CLI 返回 75，提示再次 pull 确认当前内容。daemon 尚未提交的上传删除临时文件；已经原子替换的内容不会回滚。

pull 在本地写入临时文件，完整性校验通过后才替换指定目标；中断只删除临时文件，保留已有目标。输出到 stdout 前也先完成校验。

### 4.11 本地修改与目录查询

修改文件采用 pull → 本地编辑 → push。例如：

```bash
xrun win1 pull 'D:\valle\src\main.rs' ./main.rs --json
# 使用本地 AI 编辑工具修改 main.rs
xrun win1 push ./main.rs 'D:\valle\src\main.rs' --expect '<sha256>'
```

`<sha256>` 替换为 pull JSON 中返回的原文件摘要；单人使用时可以不带 --expect。xrun 保持传输字节不变，CRLF、BOM 和文本编码由本地编辑工具负责保留。

列目录通过 exec 调用目标设备已有工具，作为普通任务执行，例如：

```bash
xrun linux1 -- ls -la /repo
xrun win1 -- cmd.exe /D /C dir 'D:\valle'
xrun win1 -- powershell.exe -NoProfile -Command "Get-ChildItem -LiteralPath 'D:\valle'"
```

### 4.12 基础截图

图形验证有两条路径：

- **桌面程序**：通过 `xrun <设备> screenshot` 拍摄主显示器当前画面。
- **网页或无头渲染**：通过 exec 运行项目的截图脚本，脚本生成图片后用 pull 取回。xrun 不提供独立的浏览器截图接口。

例如，项目已有无头浏览器脚本 `scripts/screenshot.js`，输出 `artifacts/page.png`：

```bash
xrun linux1 -C /repo -- node scripts/screenshot.js
xrun linux1 pull /repo/artifacts/page.png ./page.png
```

页面地址、视口、交互步骤和截图时机由项目脚本决定；xrun 负责执行、返回状态和传输图片。这条路径可以在没有桌面的 Linux 设备上使用。

**桌面截图命令**

```bash
xrun win1 screenshot ./screen.png
```

daemon 拍摄当前用户图形会话中的主显示器，按原始分辨率编码为 PNG，通过文件传输协议发送。CLI 校验完整摘要后保存到指定本地文件；省略路径时保存到系统临时目录中的唯一文件。stdout 只输出本地绝对路径，AI 看图工具直接打开该路径。本地相对路径以 CLI 当前目录为准；目标路径、临时写入、校验后替换和中断清理沿用 pull 的文件保存规则。截图仅接受本地文件目标。

`--json` 返回 `path`、`device_id`、`width`、`height` 和 `captured_at`；截图时间采用目标设备的 UTC 时间。PNG 最多 64 MiB。截图创建 screenshot Job，结果保存尺寸、时间、字节数和摘要，实际 PNG 保存为独立附件，不写入命令日志。

调用方决定何时拍摄当前画面。截图与任务分别调用，不自动等待程序退出或判断界面是否就绪。例如：

```bash
xrun win1 -C 'D:\valle' -- cargo build
xrun win1 start -C 'D:\valle' -- 'target\debug\app.exe'
```

后台提交输出任务引用，例如：

```text
win1/k3m9x2
```

后续使用实际返回的短 ID；这里的 `k3m9x2` 仅为示例。先查看日志，确认窗口已显示后截图，检查完成再结束程序：

```bash
xrun win1 logs k3m9x2 --tail 30
xrun win1 screenshot ./screen.png
xrun win1 kill k3m9x2
```

只读截图在连接中断后可以重试，返回重试时重新拍摄的画面，以 `captured_at` 标明时间。

| 平台 | 首版要求 |
| --- | --- |
| macOS | daemon 在用户登录会话中运行；缺少屏幕录制权限时返回 PERMISSION_DENIED |
| Windows | daemon 在用户的交互会话中运行；锁屏时返回 SCREEN_LOCKED |
| Linux | 支持 X11 图形会话；Wayland 本版返回 SCREENSHOT_UNAVAILABLE；没有图形会话时返回 NO_DISPLAY |

图形后端不可用时返回 SCREENSHOT_UNAVAILABLE；采集或 PNG 保存失败返回 SCREENSHOT_FAILED。Windows 将临时 PNG 路径交给采集工具前关闭文件句柄，读取后自动删除。基础截图只包含主显示器的当前画面；显示器或窗口选择、自动缩放、裁剪和录屏不进入本版。

### 4.13 本机状态、设备信息与存储

`xrun status` 显示本机状态和设备列表。本机部分包含身份、版本、服务安装/运行/连接状态、暂停和全体信任，不依赖远端 daemon。实例运行通过文件锁判断，连接状态使用 daemon 写入的本地运行记录。未加入时返回 0；已加入但列表查询失败时仍显示本机状态，注明列表不可用并返回 125，不把所有设备标成离线。

CLI JSON 包含 `local`、`devices`、`server_error`；`server_error` 表示中转或网络查询错误。未加入或查询失败时 devices 为 null。App 另外从本地签名清单返回 `network_id`、`manager_id`、`manager_name`、`is_manager` 和 `relay_addresses`，离线也能查看角色。

设备列表与 info 中，`device_id`、`name`、`admin`（管理设备）、`revoked` 来自本机已验证清单。status 的 `online` 仅表示中转报告该成员的控制连接存在；未知 ID 不显示，已知撤销成员标记为未连接。中转可能误报连接，缓存也可能尚未收到撤销，不能据此确认目标可执行或成员清单已同步。列表的系统、主机名、版本等可选元数据为 null；CLI 显示 relay-connected/disconnected，App 显示“中转报告已连接/未连接中转”。

info 只连接指定目标，经端到端身份和清单验证后确认 `online` 并读取 `os`、`arch`、`hostname`、`version`、`execution_user`、`default_cwd`、`last_seen`，同时保留清单同步。目标不可达时显示已验证成员记录，online 为 false，可选元数据为 null。状态不作为执行授权依据。后台清单同步照常执行；revoke 继续查询端点签名回执，不用中转连接列表代替送达确认。

不在后台枚举工具或查询版本；需要查看 PATH 和工具时通过 exec。

| 位置 | 内容 |
| --- | --- |
| `~/.xrun/identity.toml` | 私钥、证书、设备 ID/名称、网络根、网络/管理 ID、地址及首次配对结果，整体原子保存 |
| `pending.toml` | 配对前持久化的私钥、根证书和指纹，身份保存后删除 |
| `manager/root.key`、`manager/root.pem`、`manager/manager.db` | 仅管理设备持有的根密钥、权威成员清单、邀请摘要与签名配对结果 |
| `roster.db` | 本机验证过的最高版本签名清单，不能当作可随意删除的缓存 |
| `last-address.json` | 网络根指纹和上次成功地址，只用于尝试顺序 |
| `daemon.toml` | 单独允许/拒绝、全体信任、暂停及代次、默认目录、环境、任务并发上限、附件保留天数 |
| `submissions.sqlite` | 本机 request_id、来源/目标 ID、根指纹、db_id、请求摘要、提交时间和任务引用；保留 7 天 |
| `daemon.db` | 统一 Job、进程身份、去重、分块日志和附件元数据；日志序号与内容同事务保存 |
| `attachments/<时间>_<随机 ID>.blob` | 收发文件与截图的独立副本，原始名称、大小和校验值随活动摘要保存；默认保留 30 天 |
| `daemon-runtime.json`、`daemon-ipc.json` | 当前 daemon 代次、连接状态，以及私有 IPC 端点和随机凭证 |
| 服务日志、`daemon-dev.log` 或前台 stderr | 运行诊断；开发版 daemon 日志使用 daemon-dev.log |
| 系统临时目录的 `xrun-pull-*`、`xrun-screen-*.png` | 省略目标路径时取回的文件和截图，由系统清理 |

Windows 使用 `%USERPROFILE%\.xrun`。Unix 私有目录 0700、私有文件 0600；Windows 仅当前账户和 SYSTEM 访问。数据库和日志按敏感数据管理。

Job 记录来源、受理时间、类型、参数、状态和结果。文件操作记录方向、路径、字节数与结果；截图记录来源、时间和字节数。流式执行保存参数、时间、输入输出字节数和结果，不保存输出日志；转发保存连接操作记录，不保存转发内容。环境值、stdin、脚本、文件和图片原文不写入 Job 数据库，文件和图片以独立附件保存；程序参数、输出与附件都可能包含敏感数据。

桌面端“活动旅程”将其他设备在本机执行的可靠命令、文件收发、截图、流式命令和端口转发按受理时间 `created_at_ms DESC, job_id DESC` 排列，所有类型共用一条时间线和分页游标。游标包含数据库代次，数据库被重置后明确报错。查询不连接远端；状态等内部轮询不生成活动。所有操作从受理开始可见，并更新原 Job 的状态、结果与附件。活动摘要持续保留，已结束命令的输出仍按 7 天清理。

文件附件从校验完成的接收临时文件或发送时的不可变快照复制，截图保存实际发送的 PNG 字节，不依赖原文件后续是否改动或删除。缓存仅位于私有数据目录，不将原始路径用作缓存路径。桌面端可预览不超过 8 MiB 的 PNG/JPEG 和不超过 1 MiB 的完整 UTF-8 文本；其他格式或大小通过原生“另存为”保存。附件留存失败不会改变已完成传输的结果，详情明确展示留存错误。

`attachment_retention_days` 默认 30，范围为 0–3650 天，0 表示长期保留。设置可在加入网络前保存，保留已有权限和执行环境。缩短期限立即清理到期副本，正常运行的后台服务或活动页每 10 分钟检查；设备和 App 均未运行时，下次运行再清理。到期附件立即禁止预览和导出，摘要保留过期状态，原文件不受影响，已清理副本不能恢复。不提供历史数据迁移或附件补录。

### 4.14 回环端口转发

```bash
xrun cloud1 forward 8080:3000
xrun mac1 forward 0:3000 --json
```

`forward [本地端口:]远端端口` 省略本地端口时使用相同端口；本地端口 0 请求系统分配。CLI 只监听本机 `127.0.0.1`，输出实际地址；daemon 只连接目标设备的 `127.0.0.1`，失败后尝试 `::1`，远端端口为 1–65535。不能指定任意远端主机、暴露到本机所有网卡或访问对方内网。

每条本地 TCP 连接独占一条端到端会话，可以借用本机 daemon 的空闲缓存，也可以新建连接；借用前通过 SessionProbe 重新检查授权。原始字节双向传输，两方向独立背压，`end` 表示写半关闭，另一方向仍可继续接收。双方确认 EOF 后关闭会话，不归还缓存。

forward 保持前台运行，Ctrl+C 或本机终止信号结束监听并关闭连接；中断的 TCP 连接不恢复，新连接重新接通。撤销、deny 和暂停关闭已有转发会话。没有可靠任务 ID、去重或输出日志；同机其他进程也能访问监听的回环端口。

CLI 每个转发进程最多 32 条本地连接，daemon 最多 32 条转发连接；仍受中转会话与总连接上限约束：Rust 中转每来源 IP 最多 16、每目标最多 32 个会话；Cloudflare 中转每网络最多 8 个会话。每方向使用有界队列和分块传输；慢接收端不会无限缓冲。

### 4.15 非终端流式执行

```bash
xrun cloud1 -i -- cat < ./large.bin > ./copy.bin
xrun cloud1 -i -C /repo --timeout 600 -- tar -cf - artifacts > ./artifacts.tar
```

`-i`（`--interactive`）实时传递 stdin 和输出，没有 PTY/ConPTY，不提供终端尺寸、原始按键或远端交互 Shell 支持。程序、参数、工作目录、环境和进程管理沿用执行规则，默认超时 1800 秒，0 表示不限时。

- 创建 stream_exec Job 和本机提交记录，提供 jobs/wait/kill 和请求去重；不留存 stdin/stdout/stderr，仅记录传输字节数，logs 返回 LOG_UNAVAILABLE。
- 输入按最大 64 KiB 分块直接写进程管道，不受可靠任务 1 MiB 总量上限限制，不先读完整个输入。
- 本地 stdin EOF 关闭远端 stdin，stdout/stderr 独立继续传回；输出为原始字节，慢读通过有界队列和背压限制内存。
- 返回进程退出码、信号或超时 124；CLI Ctrl+C 关闭连接并返回 130，目标清理受管理进程。连接失败不自动重启程序，执行结果或副作用需要调用方自行确认。
- CLI/网络断开、deny、暂停、已知撤销或 daemon 停止都会清理受管理进程；不保证终止脱离进程组的进程。
- 与 `start`、`--json`、`--stdin`、`--script`、`--request-id` 互斥；与可靠任务共享执行并发上限。

需要大文件或目录走管道时由调用方组合 tar 等工具；流式模式不自动提供文件摘要、断点续传或 SSH 生态兼容。需要断线后继续执行并查询结果时使用普通可靠任务。

## 5. Job 语义

exec、stream_exec、push、pull、screenshot 和每条 forward 连接都是独立 Job。`jobs`、`wait`、`kill` 和桌面活动旅程读取相同模型；`logs` 只适用于留存输出的 exec。数据库结构和字段见 [统一 Job 存储](job-storage.md)，唯一建表定义为 [schema.sql](../src/store/schema.sql)。

所有业务请求都有来源范围内的 request_id，并携带目标 db_id。规范化摘要包含操作类型与不可变参数；相同 ID 和摘要返回同一 Job，参数不同返回 REQUEST_CONFLICT。连接绑定的重复请求返回 `accepted` 且 `fresh:false`，只返回记录，不重开进程、文件流或 TCP 连接。exec 保留断线后继续执行的语义；其他类型连接中断后清理，无法确认的结果标记 lost，重启一律不自动重跑。

### 5.1 状态

daemon 收齐并校验执行请求，检查来源，先按 `(source_device_id, request_id)` 去重。已有请求返回原任务，不受当前并发名额影响；新请求才检查并发、持久化启动意图并创建进程。返回任务引用；前台订阅输出，start 保存并输出任务引用后归还或关闭会话，任务独立运行。

新请求遇到 `DEVICE_BUSY` 时，在持久化启动意图之前直接拒绝，不创建失败任务，也不写去重记录。CLI 收到这一明确拒绝返回 125；稍后用相同 request_id 和参数重试可以正常受理，首次受理后才进入去重规则。

| 状态 | 含义 |
| --- | --- |
| accepted | 已持久化业务意图，尚未开始执行 |
| running | 操作正在执行；命令进程已启动 |
| succeeded | 操作成功；命令的退出码为 0 |
| failed | 操作失败，包括未启动、文件错误和非零退出；保留具体结果与错误 |
| canceled | 已确认受管理进程全部停止 |
| timed_out | 超时终止完成，受管理进程全部停止 |
| lost | 已受理任务因崩溃、存储或收尾故障无法确认最终结果，可能执行过或有遗留进程 |

最终状态持久化后不被迟到事件覆盖。存储失败时不能把未持久化结果报告为确定结果；初始记录写入失败时不启动进程。持久化的错误说明和输出不完整原因分别最多 1024 UTF-8 字节，超出保留原因前缀并附截断标记，避免诊断内容撑破任务响应上限。SQLite 使用 WAL 和 FULL 持久化，去重键有唯一约束。

### 5.2 提交、去重与恢复

- CLI 每次普通调用生成新 request_id；连接重试沿用它。
- 会话开始收到 `db_id` 后，发送请求前先持久化本机提交记录；收到任务引用后补全。SIGKILL 也不会丢失已发送提交的 ID。
- daemon 保存规范化请求的 SHA-256：覆盖程序、参数、目录、环境覆盖值、解析默认值后的实际超时、Shell，以及 stdin/脚本长度和摘要。相同 ID、相同摘要返回同一任务；不同摘要返回 `REQUEST_CONFLICT`。去重记录不随日志删除。
- `xrun recent` 只列本机最近 24 小时的提交记录，区分已确认/未确认；明确未发送或已被拒绝的记录注明未受理，不显示为结果未确认。不广播查询设备、不猜测任务当前状态。远端结果通过 `xrun <设备> jobs --request-id <ID>` 查询。
- 显式重试时重新提供同一组参数和输入，传入原 `--request-id`。原请求受理过就返回原任务；未受理就受理一次。
- 本机记录中已有 ID 的重试，校验网络根、来源与目标设备 ID；来源身份或根不匹配返回 `IDENTITY_MISMATCH`，指定目标不匹配返回 `DEVICE_MISMATCH`，不发送执行请求。更新地址和证书不改变这些绑定。
- 重试带原 `db_id`；目标数据库已重建时返回 `DB_RESET`，不执行。查询可以查看当前数据库，但查询不到原请求不能解释为此前未执行。
- 提交记录已经删除、或者从其他 CLI 使用未记录过的 ID 时，只保证当前数据库内的去重，无法承诺跨数据库重建的恢复。结果不明时先到目标设备确认。

需要再次执行时使用新 ID；xrun 不承诺任意两次相同命令只执行一次。

### 5.3 断线和重启

| 事件 | 行为 |
| --- | --- |
| 提交前目标离线 | 返回 DEVICE_OFFLINE、退出码 125，不排队，可以重试；已提交任务在断线后无法确认结果时返回 75 |
| CLI 退出或会话断开 | 任务继续运行，可重连查询和补读 |
| daemon 与中转断开 | daemon 继续执行、计时和记日志；断线期间无法远程查询 |
| 中转重启 | 会话中断，任务不受影响 |
| daemon 正常退出 | 停止接收请求，取消任务，等待完整执行与文件清理结束并持久化结果；8 秒内未完成明确报错，不以成功退出代替收尾 |
| 存储出错 | 返回 STORAGE_ERROR，不宣称未持久化结果已确定 |

控制连接每 15 秒 ping，45 秒无响应判离线；断线后带抖动指数退避重连，最长间隔 30 秒。撤销或凭证错误会阻止业务访问，不自动注册新身份；当前重连循环仍重试并记录错误。本机身份文件改为另一个设备或网络时停止当前实例；证书更新依 3.3 处理。

### 5.4 daemon 崩溃

记录 boot_id、主进程 PID、进程启动时间及进程组或 Job Object 标识。重启后不重跑任务：

- Windows：Job Object 的 KILL_ON_JOB_CLOSE 清理受管理进程。
- Unix 系统已重启：原进程不存在。
- Unix 同次系统启动且能证明进程身份：终止原进程组。
- Unix 无法证明身份：不凭旧 PID 杀进程，标记 `leftover_possible: true`，显示 PID/进程组供人工处理。

未完成任务转为 lost，退出码为 null、错误为 RESULT_LOST，不再占用并发名额。lost 表示结果丢失，不保证遗留进程已停止，也不表示副作用已撤销。

### 5.5 取消、等待和日志

kill 幂等；启动、取消和自然退出按 daemon 的最终持久化状态协调。发送前目标离线、身份被撤销或请求明确被拒绝时返回 125；取消请求可能已送达时最多等待 10 秒确认，未确认返回 75。不排队保存取消请求。

wait 在任务进入最终状态后回复；默认一直等待，`--timeout` 只限制本次等待，不取消任务。结束后输出最后 N 行，默认 40，随后返回任务结果。JSON 模式将尾部日志放入结果字段，不混入额外文本。

输出按字节处理，每块最多 32 KiB，带单调 seq、stdout/stderr 标识和 Base64 数据。同一流内有序，跨流按 daemon 观察的顺序。

每个输出流先攒批，达到 32 KiB、首字节等待 50 ms 或 EOF 时提交；50 ms 从首字节计时，后续小块不会延后期限。全库写入经容量 64 的有界队列交给专用阻塞线程，事务成功后才通知订阅者；队列满时对采集端施加背压。进程结束或取消时排空已采集批次后再提交最终状态，磁盘失败按日志不完整处理，不把未持久化输出报告为成功。

Linux 使用 pidfd 等待进程退出，内核或沙箱不支持时保留轮询回退；仍通过 `waitid(WNOWAIT)` 观察退出，清理进程组后再回收主进程。任务列表在 SQL 中分页，并按 1 MiB 响应预算截断，返回可选 `next_offset`；CLI 自动继续查询至请求条数或本页结束。单个任务受理前校验响应预算，并为后续状态及单块日志留出空间。运行中数量用索引计数，不加载全部历史；已经验证且内容未变的成员清单、成功连接地址不重复写盘。

daemon 先落本地日志，再通知订阅者；任务状态更新同样发出通知，订阅者无需等待固定轮询周期。订阅者按自己的速度读磁盘；慢 CLI 不阻塞任务。重连按最后 seq 补读；Job 包含 last_log_seq、output_complete、output_loss_reason。

| 限制 | 默认 |
| --- | --- |
| 单任务日志 | 64 MiB，超出继续排空输出但不保存，标记 TRUNCATED |
| 日志总量 | 1 GiB，先删除已结束的旧日志，仍不足则截断 |
| 已结束日志保留 | 7 天；任务和去重记录继续保留 |

logs 只适用于 exec，其他类型返回 LOG_UNAVAILABLE。默认读取请求时的快照；follow 补读后继续订阅；after 指定序号；tail 由目标端按日志序号倒序读取并截取最后 N 行，只传所需尾部。`logs --tail 0 --follow` 从查询到的当前任务序号开始，不下载历史日志。日志截断提示 LOG_TRUNCATED，已清理提示 LOG_UNAVAILABLE，输出仍可用的日志后返回 1；其他采集失败提示 LOG_INCOMPLETE。目标已撤销时返回 DEVICE_REVOKED，未撤销但离线时返回 DEVICE_OFFLINE，这两种日志查询失败均为退出码 125。磁盘失败要明确报告。

## 6. 协议

### 6.1 中转接口与配对通道

外层 WSS 握手携带 `X-Xrun-Protocol: min-max`，中转选择共同的最高协议并在升级响应返回整数；没有交集时拒绝。`X-Xrun-Version` 仅供诊断。所有接口均位于固定随机路由下；中转不读取成员清单、不存储设备元数据。

status、control 和 connect 连接建立后，中转先发送 challenge（随机 128 位 nonce），5 秒内需收到 authenticate。凭证包含设备 ID、成员证书、网络根证书和设备私钥对 `{network, device, path, nonce}` 的签名；path 不含随机路由。中转检查：根证书公钥指纹与网络 ID 一致；成员证书由该根签发、在有效期内且属于声明的设备 ID；签名有效。管理设备的控制凭证另附网络根私钥对同一内容的签名。凭证不能跨接口、网络或挑战重放。连接验证通过后才不再计入未认证名额。

| 接口 | 认证与职责 |
| --- | --- |
| `WSS /<随机路由>/networks/{network}/status` | 需成员凭证；返回当前已验证控制连接的设备 ID，仅供显示连接状态和选路；info 另行验证目标状态 |
| `WSS /<随机路由>/networks/{network}/control` | 需成员凭证；按凭证中的设备 ID 注册路由，维持心跳并接收会话通知 |
| `WSS /<随机路由>/networks/{network}/connect/{target}` | 成员凭证可接通任意在线目标；不带凭证只能接通已用根私钥证明的管理设备，用于加入和过期续期 |
| `WSS /<随机路由>/networks/{network}/attach/{target}/{generation}/{session_id}` | 不另带凭证；代次与会话 ID 只发给已验证的控制连接，绑定后接入一次 |

控制消息有 challenge/authenticate、hello_ack、incoming/reject、connected、status、error；心跳使用 WebSocket ping/pong。每设备路由只保留最新控制连接；只有同一设备的新凭证能替换它，替换时关闭旧会话并作废待接入请求。控制代次为随机 128 位值，只发给该控制连接，用于绑定附件连接。

会话 ID 为随机 128 位值，只通知目标控制连接，绑定网络、目标与控制连接代次；10 秒未接入即结束。两种中转均限制不带成员凭证的配对会话每目标最多 4 个、每网络最多 256 个控制映射。Rust 中转已认证来源按网络和设备 ID 计数，每个来源最多 16 个会话；匿名来源仍按 IP 限制 16 个。每目标最多 32 个，全局最多 4096 个会话和 4096 个控制映射，另受 512 条 TCP 总连接和 daemon 的 32 个会话限制；未认证连接的 IP 防滥用限制继续保留。它在每方向一次读写，利用慢读反压；Cloudflare 每网络最多 512 个 WebSocket 和 8 个来源会话，用每方向 4 MiB 确认窗口限制缓冲，未确认密文总预算最多 64 MiB。CF 每个已认证来源最多 4 个会话，匿名来源按 IP 最多 4 个；普通连接使用总容量中的 7 个，最后 1 个仅供当前控制连接已用网络根私钥证明的管理设备来源使用。匿名配对不占该预留名额。来源额度满时只回收该来源自己的空闲缓存。这是资源公平性限制，不保证所有管理请求同时成功，也不代替端点撤销检查。两者仅接受最大 64 KiB 的密文二进制帧。Rust 中转按会话任一方向的最近活动判断 5 分钟整体空闲，并保留独立的写入阻塞超时；CF 使用方向确认窗口和活动期限。

管理设备新增或撤销成员后立即尝试同步全部在线端点；成员同步和撤销回执查询并发联系最多 2 个已知未撤销端点，每个状态请求最多等待 5 秒；公共 HTTPS 中转包含更多握手往返，上限为 20 秒。建连遇到 `SESSION_LIMIT` 时最多尝试 4 次，间隔 50、100、200 ms，仍受上述总超时限制；其他错误不重试。日常设备操作从本地已验证的签名清单解析目标名称或 ID，直接新建或借用业务会话；`status` 只查询中转连接列表并过滤本地已知撤销，`info` 只查询指定端点。新建端到端会话时交换签名清单，复用前比对成员版本，发生变化时重建会话并重新交换。daemon 每次建立控制连接前同步一次：优先联系在线管理设备，管理设备离线时从随机起点选择其他在线端点。后台兜底同步每 5 分钟加最多 1 分钟随机抖动执行一次，按同样优先级选择端点，后备端点按游标轮换；管理设备联系失败时才尝试后备端点，不遍历全网。每次端点同步都需要经中转建立连接并完成一次双向 TLS 握手。端点保留最高版本，离线设备重连时可从其他在线端点获得已发布更新，不要求管理设备在线。完整成员清单、设备元数据和签名回执均在端到端 TLS 内传递。

配对在内层验证管理设备 TLS 后传递带协议范围的 PairRequest；管理设备在消费邀请或签发前协商协议，响应包含范围与选中的协议。内层业务 TLS 后双方交换完整签名清单与协议范围，再检查成员公钥、撤销和业务权限。代码中 `/devices`、`/invites`、`/admin/revoke` 仅为客户端核心库的本地适配入口，不是中转公开 HTTP 接口。

### 6.2 会话消息

新建端到端 TLS 后直接使用 WebSocket 帧，不再进行内层 HTTP Upgrade。来源连续发送带发布号、协议范围的签名清单和会话用途，省去用途声明的一次往返；执行参数和输入不提前发送。双方协商协议并验证签名清单和成员身份后处理会话用途。State 返回成员状态和回执后关闭；Execute 检查本机执行授权后，daemon 发送 `{"type":"ready","device_id":"…","db_id":"…","default_cwd":"…","version":"…","protocol":{"min":1,"max":1},"selected_protocol":1}`。CLI 核对协议选择和目标 ID 后才发送业务请求；控制连接也通过外层握手协商协议。

Execute 会话可以依次处理多个请求，同时只有一个在途操作。daemon 在每次请求前检查来源授权、暂停代次和证书期限。缓存复用前先发送 `{"type":"session_probe","roster_version":N}`，目标重新检查成员版本及访问条件，返回包含当前默认目录和数据库 ID 的 ready。探测最多等待 5 秒；失败时可以关闭旧连接、重新建立会话，因为此时尚未发送业务操作。

请求头为 JSON 文本 `{"type":"request","request":{"op":"…",参数…}}`。长度和 SHA-256 在执行或上传请求头中发送；stdin、脚本和文件内容用二进制块，每块不超过 64 KiB，最后发送 `{"type":"end"}`。下载和截图先返回 `file` 头（含长度和摘要），再返回二进制块和 end。

成功响应的顺序如下；`end` 结束当前输入、文件或日志流，`complete` 表示这个请求的全部响应已发出，二者含义不同：

| 操作 | 响应顺序 |
| --- | --- |
| 前台 exec（`follow: true`） | `job` → 带任务状态的 `logs` → `end` → `complete`，全部在提交会话内返回 |
| 后台 exec（`follow: false`）、jobs、wait、kill | `job` 或 `jobs` → `complete`；wait/kill 等待最终持久化状态 |
| logs | 带任务状态的 `logs` → `end` → `complete` |
| push | `accepted`（含 Job 与 fresh）→ 接收并校验上传数据 → 写入确认 `file` → `complete` |
| pull、screenshot | `accepted` → `file` 头 → 二进制块 → `end` → `complete` |

CLI 收到操作的完整结果后消费 `{"type":"complete"}`；通过本机 daemon 调用时，再经私有 IPC 发送 `{"local":"release"}`，收到 `{"local":"released"}` 后完成归还。每条本机 IPC 连接只处理一次操作，后台 daemon 持有的远程会话可以跨 CLI 进程复用。未读完、出错、本机中断或提前归还都会丢弃连接；归还阶段最多等待 2 秒，失败只影响缓存，不推翻已确认的业务结果。前台执行仅在断线恢复时另开日志会话，按最后序号补读，不重新提交任务。

CLI 的 start 入口使用 exec，并把解析后的实际超时发给 daemon；jobs 带 ID 时查详情，不带时分页查列表。info 将本机签名成员记录与经过端到端验证的目标状态合并。push 的本地源（包括 stdin 临时文件）和 pull、screenshot 的本地保存路径只由 CLI 处理，不发送给 daemon。

文件、截图和输入传输结束时校验完整摘要，失败返回 CHECKSUM_MISMATCH，删除未提交的临时文件。格式或顺序错误返回 INVALID_MESSAGE 或 INVALID_BODY 并关闭会话。上传在 daemon 上分块落临时文件；下载先生成私有临时快照，使摘要对应发送的字节。文件请求取消时，阻塞工作仍持有路径锁和并发名额，复制及发布前检查取消；已经开始原子替换的结果按未确认处理，Job 以实际发布结果为准。截图取消先终止并回收采集子进程，再清理临时文件和释放名额。执行任务继续运行。

流式执行先返回 accepted，再使用 stream_ready、带 stdout/stderr 标识的二进制块、stdin end、stream_exit 与退出确认；端口转发先返回 accepted，再使用 forward_ready、原始字节块、end 和 EOF 确认。两者独占端到端会话，按 4.14、4.15 清理，完成后关闭，不归还缓存。

目标 daemon 等待下一条请求最多 90 秒；本机缓存按 2.2 提前回收空闲连接。daemon 收尾时等待内层 WebSocket 关闭握手，最多 30 秒，避免中转仍有排队密文时提前断开外层通道；停止 daemon 可立即取消等待。

错误统一使用 `{"type":"error","code":"错误码","message":"说明"}`，message 去掉已有的同一错误码前缀，CLI 只拼接一次。

Rust 内部用 `error::ErrorCode` 和 `CodedError` 标识错误，协议边界保留现有 code 字符串。添加 anyhow 上下文或修改说明不会改变分类；未知远端错误码保留原值，不按字符串前缀推断含义。退出码同时取决于请求阶段：发送前失败、明确拒绝与送达后结果未确认分别处理，不能只按错误码直接映射退出码。

可靠提交在记录“可能已发送”前完成协议检查和消息编码，本地不支持的操作返回 125，不进入恢复查询。开始写网络之前即标记可能发送，写入失败仍可能已送达，保留查询恢复及退出码 75 的语义。授权快照与显式重载保留原始错误码；Windows 文件替换通过卷标识和文件 ID 检测，显式重载直接重读，不被相同长度与时间戳挡住。

### 6.3 版本和限制

发布版本、协议版本和签名格式分别维护。发布版本用于 `xrun --version`、设备信息和诊断。本机 IPC 仍要求 CLI、App helper 与本机 daemon 的发布版本一致，替换程序后需要重启 daemon。

网络协议从整数 1 开始。当前组件交换支持范围 `{"min":1,"max":2}`，选择共同的最高版本；无交集、范围非法或 Ready 的选择不一致，返回 `VERSION_MISMATCH`，不发送业务操作、不消费配对 Token。外层 WSS 请求头 `X-Xrun-Protocol` 使用 `min-max`，升级响应返回选中的整数，保存在该连接的传输上下文中，并带入端到端隧道；外层选择与端到端协商分别维护。`X-Xrun-Version` 仅供诊断。Cloudflare 部署写入 `XRUN_PROTOCOL_MIN` / `XRUN_PROTOCOL_MAX`，与代码实现的范围一致。端到端清单交换、配对请求与响应、Ready 也携带范围；Ready 与配对响应包含 `selected_protocol`。

协议 2 在外层隧道增加 `{"type":"cache_state","idle":true|false}`，只允许已认证来源发送，中转原样确认，不转发给目标。来源消费 `Complete` 且本机 CLI 归还后才声明空闲；复用先声明活跃并等待确认，再发端到端探测，最后发送业务。空闲来源禁止发送密文；满额时中转可关闭最早声明空闲的配对连接。静默中的长任务不因此变成空闲。CF 将协商版本与空闲时间写入 WebSocket 附件，休眠恢复后仍按相同规则判断；协议 1 不发送此消息，不启用新版缓存。

普通消息忽略可以安全忽略的未知字段，必需字段和未知消息类型仍拒绝。正式发布前直接更新业务协议，不维护历史 Job 消息或混合版本运行；CLI 与 daemon 应使用同一份构建。外层中转协议范围只表示传输能力，不构成历史业务消息兼容承诺。签名记录、证书证明与本机安全配置继续严格拒绝未知字段。

签名有效载荷为 `xrun/sig-v1/{用途}\0` 加固定 JSON 字节，与发布版本无关。永久测试向量固定成员清单及根证书摘要、配对回执、清单回执和中转证明的字节、签名与用途隔离。改变签名记录结构或编码必须提升签名格式，并明确重签与过渡方案；普通发布号变化不会使已有签名失效。

此次统一 Job 使用 daemon 与 submissions schema 2；不迁移旧数据、不回填、不保留旧接口。更旧的活动库和提交记录库先完整备份，再以事务重建；设备身份、授权和成员清单保留。App 打开时正常停止旧 daemon、换用当前 helper 并恢复先前运行状态，活动查询等待存储准备完成。CLI 更新前按 4.2 等待任务结束并停止本机服务，参与业务操作的端点统一更新。当前发布版本为 `0.1.0-rc.4`，各发布入口统一维护。

单条业务消息不超过 1 MiB，可靠执行用 stdin/脚本各不超过 1 MiB，截图 PNG 不超过 64 MiB。接收时检查，超限拒绝。push/pull 文件与 push 从 stdin 读取时不设固定总量上限，按 64 KiB 分块读写，附件缓存也按块保存与导出；截图缓冲上限独立于文件传输。任务列表分页，CLI 可逐页展示。流式输入和 TCP 转发不设固定总量上限，单块最多 64 KiB，内存受有界缓冲约束。

程序、参数、环境和路径不得含 NUL；输入与文件原始字节不受此限制。Windows 环境名大小写重复、负数超时、未知字段或类型错误返回 INVALID_REQUEST。

## 7. 实现与验证

### 7.1 代码组织与打包

根目录 `rust-toolchain.toml` 固定 Rust 工具链版本及 rustfmt、clippy 组件；本地开发、三平台测试和 Package 工作流统一读取该文件。升级时显式修改固定版本并重新验证，CI 保留 `-D warnings`。

Rust workspace 的核心 package 提供 CLI、daemon 和 Rust 中转；桌面 package 位于 `desktop/src-tauri`。按现有职责划分：membership 管理签名清单与权威状态，network 处理创建/加入和端点同步，relay 接通外层连接，secure 建立端到端 TLS，ipc/session/pool 处理本机通信、CLI 会话与后台连接缓存，daemon/store 管理可靠任务，process 处理原生进程，transfer/screenshot/forwarding/streaming 处理相应业务，service/control/history 提供本机服务与只读历史。Cloudflare Worker、部署脚本和 workerd 测试位于 `cloudflare/`。

支持的公开边界为 `xrun::client` 的用户操作、设置和只读历史，`xrun::runtime` 的进程入口，以及 `protocol` / `error` 的协议类型和错误分类。App 通过这些边界访问核心；config、network、daemon、store、secure 等实现模块保持私有。`xrun::testing` 仅供集成测试夹具，不属于稳定应用 API；`deny(unreachable_pub)` 检查意外公开，client/runtime 边界要求文档注释。

`cli.rs` 只负责命令入口，参数、本机操作、远端选择、可靠提交、任务查询、日志、文件和转发分别位于 `src/cli/`。`daemon.rs` 持有共享资源并负责启动、恢复和退出；`src/daemon/requests.rs` 统一检查会话权限并建立 Job 生命周期，再分发给可靠任务、文件和连接型操作模块。各操作保留接收输入后的权限复查、并发配额和进程启动门锁。`network.rs` 保留对外 API 与本机网络状态校验，连接认证、设备同步、链接校验、创建、配对和续证分别位于 `src/network/`；新增请求种类必须显式加入穷尽分发。

App 使用 Tauri 2、React、TypeScript、Vite 和 Bun，生产包包含静态前端与配套 Rust helper，不包含 Bun。根目录 `bun run --cwd desktop build` 根据平台生成 macOS App ZIP 或 Windows 当前用户 NSIS 安装 EXE；`--debug` 使用调试目录。`--target` 可在同一操作系统内指定 x86_64 或 aarch64 的 Rust target，App 与 helper 按相同 target 构建，产物和缓存进入 `target/<target>/<profile>/`；默认本机构建仍使用 `target/<profile>/`。每个包包含单一架构。macOS 本地包默认 ad-hoc 签名，正式包使用 Developer ID 签名、公证 App 并附票据后打包 ZIP；Windows 安装包当前未签名。桌面包同时包含终端 CLI，用户不需要单独安装 CLI。服务使用固定位置的包内 helper，升级前正常停止。App 隐藏或最小化时暂停页面轮询，再显示时刷新；托盘只读取轻量本地运行状态，不定时校验完整成员清单。CLI 安装 macOS LaunchAgent 时，同配置已加载的服务可重新启动；运行中改变程序路径需要先停止，停止后重新加载新配置。

发布矩阵为 Linux、macOS、Windows 各自的 x86_64 / arm64，共六组。Linux 提供只含二进制的 CLI 压缩包，macOS / Windows 提供上述桌面产物，不单独分发 CLI 包；清单与文件名使用目标系统和架构，不使用构建机器的架构。自动安装脚本按设备架构选择对应清单，安装程序和用户 PATH。Package 只构建和检查 Actions 产物；独立的 Release 工作流通过手动指定成功的 Package 运行 ID，复用其产物和提交创建版本化 Release，分别提供程序、安装脚本和校验文件。

Rust 与 Cloudflare 中转使用同一套连接认证和端到端会话协议，CLI 与 daemon 不依赖中转保存成员状态。

### 7.2 自动化验证

- [Readability](../.github/workflows/quality.yml) 检查源码行长、文件规模、Cloudflare 判别联合及非空断言，并测试检查器自身。
- 三平台普通核心测试验证已有会话的输出送达与授权失效，等待上限为 5 秒。受控空闲机器另单独执行 `tests/latency.rs` 的 ignored 验收，保留输出 100 ms、授权失效 200 ms 的产品预算；共享 CI 不以这些时延作硬门槛，功能通过不能代替时延通过。
- Linux 使用当前源码构建 CLI、daemon 与 Worker，在 Rust 中转和 Cloudflare workerd 上验证端到端操作，不构建历史版本。
- [Measure performance](../.github/workflows/performance.yml) 手动对照选定 Git ref，在三平台测空闲 CPU、日志与同期查询，Linux 另统计文件读取和数据库同步；结果上传为报告，不设吞吐门槛。缓存测量与真实 CF 休眠验收按开发文档单独运行。

- Linux、Windows 的测试工作流分别覆盖 x86_64 与 arm64，macOS 测试工作流使用 ARM runner；均运行格式检查、clippy 和原生核心测试，覆盖配对、TLS、成员签名、授权、可靠任务、传输、流式执行、端口转发与故障恢复。测试直接调用中转库，不开放非 Linux 的中转部署命令。
- 核心测试包含前台提交与日志共用会话，以及独立 CLI 进程之间的缓存复用、配置更新、授权变化、数据库重建、并发请求隔离、私有 IPC 认证、提前归还、缓存上限、证书过期和上传期间源文件变化。
- Linux 使用 Xvfb 验证 X11 PNG，并以 1 MiB 主线程栈检查命令和取消路径。
- Linux 工作流另在 workerd 中运行 Cloudflare 中转测试，验证证书挑战、连接数量限制、一次性接入、断线清理和密文窗口。随后运行 `cloudflare` 的 `bun run test:interop`：本地 workerd 使用临时 HTTPS 证书和固定证书指纹，真实 Rust CLI/daemon 完成创建、配对、证书签名、可靠任务、65 MiB 文件往返、二进制流、TCP 半关闭、管理设备离线、空闲恢复与撤销。两组验证均无需 Cloudflare 凭证。互通脚本先用 Cargo 构建 CLI 和 Cloudflare 测试，复制到独立临时目录，再显式运行标为 ignore 的测试，避免运行期间被其他构建替换；普通 `cargo test` 不要求 workerd。相同测试也可通过私有 `XRUN_TEST_CF_LINK_FILE` 对已部署中转运行。
- macOS/Windows 运行前端类型检查与 UI 测试、desktop Rust 检查，生成调试安装包并检查 App/helper。macOS 解压 App ZIP 后使用其中 helper 跑 smoke；Windows 安装 NSIS 后使用安装目录 helper 跑 smoke。Linux 原生检查命令安装、PATH、重复安装和失败回滚。
- Cargo 与 Bun 缓存按系统/架构、工具链或锁文件区分。失败时上传测试子进程日志。正式签名、公证与发布产物由独立 Package 工作流处理。
- Package 工作流中 Linux / Windows 两种架构分别原生构建和运行产物检查；macOS 两组均在 ARM runner 构建，x86_64 产物通过 Rosetta 运行 smoke 与安装检查。后者验证转译环境，不代替 Intel Mac 实机验收。

App 网络界面此前通过本机 TypeScript/UI 测试、Rust 检查、App 自检与包内 helper smoke；浏览器界面验收使用隔离的模拟 IPC。每次提交的远端 CI 结果以对应 Actions 为准，已有测试记录不能代替新提交的验证；正式签名包的真实网络操作仍按下表验收，模拟邀请/撤销不算真实网络验收。

当前真实组合验收只使用 Mac 与 cloud-ubuntu，没有 Windows 实机环境。服务重启通过不代表重新登录、睡眠唤醒或整机重启通过。浏览器截图的项目脚本应明确等待页面就绪并关闭浏览器；生成 PNG 本身不代表进程正确退出。

下一次对外分发先完成 6.3 的统一升版和对应提交的 CI，再用正式签名包验证 App 的真实网络操作，检查 Mac 重新登录/睡眠唤醒和云主机重启后的服务与连接。未实现能力保持 1.3 的范围边界，不扩展为另一份规划文档。

## 8. 验收标准

以下场景需要真实运行证据。协议和任务逻辑可在 Linux CI 验证；平台进程、路径、编码和服务必须在对应系统验证。截图权限、锁屏和图形效果在有图形会话的真实设备上验收。

### 8.1 中转、身份与访问控制

| 场景 | 通过条件 |
| --- | --- |
| 部署与角色 | Linux 安装中转不生成网络管理身份；任意客户端创建网络并持有根密钥；中转主机可独立作为普通成员加入 |
| 手动与自动地址 | --port 与发布 --addr 各自生效；手动地址重启保留；自动探测失败有明确提示；每次验证指纹和 SAN，成功地址缓存仅影响尝试顺序 |
| 传输限额 | 空闲 TLS/HTTP 有超时，未认证连接、控制连接与会话并发上限生效；CF 密文确认窗口有界；accept 失败不使 Rust 中转退出 |
| 部署链接 | 固定随机路由、可重复使用、重启复用；成员邀请和中转地址分开，知道中转地址不授予设备执行权限 |
| 中转凭证 | 无凭证、他人证书、其他网络证书、错误签名或重放挑战都不能占用设备路由或查询在线设备，原控制连接不受影响；不带凭证的配对只能接通管理设备，且每目标并发有上限 |
| 加入与重试 | 管理设备 TLS 身份验证后才发送 Token；先持久保存私钥；响应丢失重试返回同一 ID；名称占用不消费邀请 |
| 管理权限 | 普通成员不能邀请/撤销或接管管理身份；管理设备不能撤销自己 |
| 端到端身份 | 中转不能解密业务、伪造客户端、将目标替换为另一成员或注入执行授权；身份来自证书与签名清单 |
| 清单持久化 | 更低版本不覆盖最高版本，同版本不同内容拒绝；清单丢失不静默重建，撤销成员不重新激活 |
| 成员与名称 | 更新地址/证书后 ID 不变；名称复用不改变旧任务 ID；已撤销目标明确返回 DEVICE_REVOKED |
| 授权 | 默认拒绝，--allow 仅管理设备与新成员互相授权，重试不覆盖单独拒绝；任务按来源隔离 |
| 全体信任 | 仅覆盖已验证未撤销成员并含未来成员；单独拒绝优先，关闭全体信任保留原白名单 |
| 暂停 | 新请求拒绝、现有会话关闭、可靠任务继续；快速暂停再恢复不复活旧会话，重启不解除暂停 |
| 管理设备离线 | 有效证书和已有授权下普通成员互控正常；加入与普通成员续期需要管理设备在线 |
| 撤销送达 | 本地签名先保存，端点同步失败不回滚；只认有效版本/哈希回执；未送达成员明确列出，重复撤销可重发 |
| 撤销边界 | 收到更新才拒绝来源，已受理任务继续；旧清单双方不能证明全网最新，紧急阻断走目标本机 |
| 中转切换 | 管理设备签名新地址，收到更新的成员使用新中转；未收到需手动恢复，不宣称全网自动迁移 |
| App 网络操作 | 角色与地址可离线显示；真实创建/加入成功，邀请默认不授权，复制仅显式点击，撤销显示未送达并可重发 |
| 服务与存储 | 各平台用户服务登录/开机/异常退出符合配置；中转不保存管理根私钥或业务内容 |

### 8.2 客户端、文件和截图

| 场景 | 通过条件 |
| --- | --- |
| 连接验证 | 指纹、证书签名、有效期和 SAN 校验；验证通过前不发 Token |
| 会话复用 | 独立 CLI 进程复用同一远程连接；每连接同时只运行一个操作，Complete 后才可归还；授权、暂停、身份、成员版本、证书和数据库变化按当前状态处理；不自动重放操作 |
| 私有 IPC 与缓存上限 | 只接受本机受保护的用户端点和有效凭证；无 daemon 时可直接连接，发送本机请求后不回退重提；每目标最多一条空闲、本机最多三条，75 秒或证书到期回收；占满操作名额时仍能认证并处理停止请求 |
| 授权 | 邀请默认只注册；显式 --allow 仅管理设备与新成员互信，第三方默认拒绝；普通成员不能生成邀请；allow-from/deny-from 修改本机调用来源，deny-from 关闭来源现有会话；revoke 需要管理身份，不要求目标在线 |
| 自启动 | Linux linger；macOS 登录 LaunchAgent；Windows 登录计划任务，无额外窗口 |
| 参数与脚本 | 空格、反斜杠、Unicode、空参数保真；--script 必须给出 Shell；PowerShell 中文脚本和 cmd ASCII 脚本正确；批处理不会被隐式执行 |
| 命令组织 | 执行、任务、传输、截图和 forward 先写设备；授权、revoke 和 status 为本机命令；未知操作被拒绝；执行入口 -- 后的参数不被 xrun 解析；文件路径不拆分冒号；完整任务引用指向其他设备时不转发 |
| 状态与任务查询 | status 合并本机状态和设备列表；中转不可达仍显示本机状态，列表不可用且返回 125；jobs 无 ID 列表、有 ID 详情，ID 与列表过滤选项互斥 |
| 执行入口 | 前台默认超时 1800 秒，start 默认不限时，显式超时覆盖默认值；start 返回可查询的任务引用；前台提交与日志共用会话，断线才重连补读；两者复用 exec，follow 不参与去重摘要 |
| 输入与输出 | stdin 超限不启动；非 UTF-8 输出原样传递；正常执行没有额外 xrun 输出；JSON 不混入人读内容 |
| 文件传输 | 仅单文件 push/pull，路径按源、目标排列；目录被拒绝；本地相对路径使用 CLI 当前目录，-C 只影响远端；push 保留远端已有目标权限 |
| 字节与管道 | 二进制、CRLF、BOM 和 NUL 原样传输；push - 按块暂存 stdin，不设固定总量上限，读取失败不提交；pull 到 stdout 先校验且不能同时 --json；push 从 stdin 可以输出 JSON |
| 覆盖条件 | pull --json 给出下载内容的完整 sha256；push --expect 与远端当前目标比较，不匹配或目标已不存在时不覆盖；不带时正常创建或替换 |
| 并发上传 | 两个内容均不同于原文件的 push 使用同一旧摘要时，只能一个成功；检测到外部修改时拒绝；不声称严格外部互斥 |
| 上传响应丢失 | push 不自动重发，返回 75；再次 pull 能看到实际内容，外部后续修改不会被重试覆盖 |
| 文件完整性 | push/pull 分块读写，内存不随整个文件增长；未收齐或哈希不符不替换目标，上传摘要计算后源文件变化被检测时保留原目标；pull 中断不损坏已有本地文件 |
| 看构建产物 | pull 输出的本地路径可直接交给本机工具打开 |
| 图形效果闭环 | 构建并以 start 启动图形程序，确认窗口就绪后截图；本地 PNG 显示预期界面，路径可直接交给 AI 看图工具 |
| 无头网页截图 | 没有桌面的 Linux 设备通过 exec 运行项目的无头浏览器脚本并生成 PNG；pull 取回后能查看网页效果，不依赖桌面截图接口 |
| 截图边界 | 主显示器、原始分辨率；macOS 无授权、Windows 锁屏、Linux 无图形会话和 Wayland 按定义报错 |
| 截图完整性 | 指定本地文件或默认临时路径均在校验后才发布 PNG，中断不损坏已有目标；新请求生成新截图，同一 request_id 只查原 Job；未授权来源不能截图，中转不保存图片内容，目标保留私有附件副本 |
| 系统授权 | macOS 受保护目录失败有明确提示；必要的服务权限在目标系统实测 |

### 8.3 任务和故障

| 场景 | 通过条件 |
| --- | --- |
| 执行闭环 | macOS、Windows、Linux 执行、等待、日志和取消都按契约运行 |
| 请求去重 | 同一来源、同一 ID、同一请求返回原任务，即使当前并发已满；更改参数/env/输入/脚本被拒绝 |
| 繁忙重试 | DEVICE_BUSY 返回 125，不创建任务、不写去重记录；释放名额后同一 ID 可以受理，之后继续按原任务去重 |
| 提交恢复 | 发出请求后、收到任务引用前 SIGKILL；recent 保留 ID；原 ID 和原输入重试只执行一次 |
| 提交失败分类 | 请求发送前连接失败或明确拒绝返回 125；开始发送后无法确认受理或执行结果返回 75，发送函数报错不被当作未发送；不把 125 一概解释为未执行 |
| 有意重跑 | 两次普通相同命令产生两次提交；不出现命令匹配拦截 |
| 数据库重建 | 有本机提交记录的旧请求携原 db_id 重试被拒绝，不启动新进程 |
| 引用稳定 | 更新地址和证书后原 device_id/短 ID 仍能查询；连接重试和 --request-id 重试使用记录中的设备 ID，名称复用不改变按 ID 的路由；旧身份已撤销返回 DEVICE_REVOKED，未撤销但离线返回 DEVICE_OFFLINE |
| 网络故障 | 在提交、启动、输出和结束阶段断线；任务不重跑，重连可补读日志 |
| 取消和超时 | 三平台停止受管理子进程；未确认不报成功；wait 超时不取消 |
| daemon 崩溃 | 按进程身份处理遗留任务，转 lost、不重跑、不占并发；不能证明身份时不误杀其他进程 |
| 遗留输出 | 脱离进程组且继承输出的后台进程不让任务永久挂住，2 秒收尾并标记 DETACHED_OUTPUT |
| 睡眠 | 睡眠计入超时，恢复后执行超时检查 |
| 生命周期故障 | 提交期间撤销/暂停不误报未受理；启动后存储失败不记 failed；正常停机等结果落盘；本地确认补写失败仍提供任务引用 |
| 查询边界 | 长参数任务列表按字节分页；tail 不下载完整日志；尾部快照与后续日志不跳号；wait 日志超时保留已确认退出码 |
| 资源与磁盘 | 并发、消息和日志上限生效；慢读不阻塞任务；存储错误不宣称确定结果 |
| 设备离线 | 提交前、只读查询或 kill 未发送时返回 DEVICE_OFFLINE、退出码 125；wait 等待已有任务结果不可确认时仍为 75；不排队执行或取消 |
| 敏感数据 | Job 表无 env 值、stdin、脚本和文件原文；附件独立保存在私有缓存，临时文件与密钥有私有权限 |
| 流式执行 | 大输入、EOF 后输出、stderr 分流、退出码、超时与慢读有界；统一 Job，断线清理且不自动重跑 |
| TCP 转发 | 只监听/连接回环；每条 TCP 连接独占新建或借用的会话，结束后不归还；多连接、双向半关闭、慢读、暂停/拒绝/撤销清理通过，单连接失败不使监听假报全成功 |
| 版本规则 | 发布号用于诊断与本机 IPC；WSS、清单交换、配对及 Ready 协商共同协议，无交集拒绝且配对不消费 Token；签名格式独立并由固定向量约束；beta.4 从协议 1 开始，旧 beta 不兼容 |
| Git 工作流 | 远端 Git 拉取和构建；文件冲突通过 pull、本地编辑、带原摘要 push 解决，再取回产物；目录查询通过 exec |

验收结果必须注明原生自动化、模拟 UI 与实机的范围；未验证的系统权限、登录、睡眠和重启不按已通过报告。
